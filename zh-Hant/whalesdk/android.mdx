## 系統要求

- **Min Android SDK**：24

- **Target Android SDK**：35

- **JDK**：17+

- **Kotlin**：1.8.22+

- **AGP**：8.5.2+

- **Gradle**：8.7+

- **架構支援**：arm64-v8a、armeabi-v7a

- **Android Studio**：建議使用 2025.1.3+；低版本如出現構建不相容請升級

- **開發語言**：Java、Kotlin

- **其他**：不支援橫屏展示。

## 整合方式

下載 `LBWhaleAppSDK-XXX.zip(內含 aar 和 Demo)` 解壓後將 SDK 目錄複製到您 `App` 級別的目錄下， 在 App 級別的 `build.gradle` 的 `plugins` 下方新增下列程式碼匯入 SDK 配置檔案

```groovy
plugins {
}
apply from: "${project.file('LBWhaleAppSDK/whale-sdk-config.gradle')}"
```

## ARouter 預編譯最佳化（推薦開啟）

SDK 內部使用 ARouter 進行路由，如需進行預編譯最佳化，請在專案級別的 `build.gradle` 中新增如下外掛：

```groovy
classpath files('./app/LBWhaleAppSDK/libs/lb-arouter-register-1.1.1.jar')
```

在 App 級別的 `build.gradle` 的 `plugins` 中新增外掛：

```groovy
plugins {
    id("com.longbridge.arouter")
}
```

開啟後將在編譯期將路由表進行預載入，如未開啟該功能，將會在 SDK Init 時讀取 dex 獲取路由表從而影響啟動耗時。

## Kapt 和 Databinding

SDK 需要開啟 Kapt 和 DataBinding 支援，如原有專案已開啟可跳過該步驟，否則請按如下方式開啟。

專案級別的 `build.gradle` 中新增下列程式碼

```groovy
apply plugin: 'kotlin-kapt'
```

App 級別的 `build.gradle` 中新增下列程式碼

```groovy
plugins {
    id("org.jetbrains.kotlin.kapt")
}
android {
    buildFeatures {
        viewBinding = true
        dataBinding = true
    }
}
```

## 初始化 SDK

在 `Application onCreate` 中呼叫 SDK 的 Init 方法進行必要資源的初始化準備，請在主執行緒呼叫該方法。

```kotlin
LBWhaleApp.init(application)
```

## 配置推送

### 方式一：走 SDK 內建渠道

SDK 內建阿里雲推送，相關的業務推送可透過該渠道推送至客戶端進行處理。

當收到推送時應用處於前臺會顯示**應用內通知**，當應用處於後臺時則會顯示**系統通知欄通知**。

如需使用內建阿里雲推送功能請在 SDK 初始化之後呼叫下面方法， `LBWhaleApp.pushService.init()` 需要在主執行緒呼叫。

```kotlin
val notificationConfig = NotificationConfig.Builder()
    .notificationIcon(R.mipmap.logo_notification)
    .notificationSmallIcon(R.mipmap.lb_push_small_notification)
    .notificationChannelId(channelId)
    .build()

//建立推送配置
val pushConfig = LBWhalePushConfig.Builder()
    .appKey(BuildConfig.ALIYUN_PUSH_APP_KEY)
    .appSecret(BuildConfig.ALIYUN_PUSH_APP_SECRET)
    .notificationConfig(notificationConfig)
    .pushCallback(object : LBWhalePushCallback {
        override fun onNotificationOpened(title: String, summary: String, extMap: Map<String, String>) {
          //當通知欄通知被點選後觸發該回調，需要在此判斷 SDK 是否正在執行
          //然後呼叫 handleNotificationOpened 方法處理點選事件, 實現頁面跳轉
          if (LBWhaleApp.isStarted()) {
            LBWhaleApp.pushService.handleNotificationOpened(title, summary, extMap)
            return
          }
          //如 SDK 未啟動，需啟動 SDK 後再呼叫 handleNotificationOpened 進行處理
        }
    })
    .build()

//初始化推送服務
LBWhaleApp.pushService.initializePush(this, pushConfig)
```

#### 廠商通道推送

SDK 內建的阿里雲推送支援相容第三方廠商通道，以達到提高推送到達率的效果。下方以 FCM 為例說明如何將 SDK 的業務訊息傳送至 FCM 訊息。

初始化 Firebase 後上報 FCM Token 到 SDK

```kotlin
FirebaseApp.initializeApp(this, options)
FirebaseMessaging.getInstance().token.addOnCompleteListener { task ->
  if (task.isSuccessful) {
    val token = task.result
    //將 token 上報到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }
}
```

在 FirebaseMessagingService 中更新 Token 以及處理訊息

```kotlin
class DemoFirebaseMessagingService : FirebaseMessagingService() {
  private val logger = SDKLogger.get(this::class)

  override fun onNewToken(token: String) {
    logger.i("onNewToken: $token")
    //將 token 上報到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }

  override fun onMessageReceived(message: RemoteMessage) {
    logger.i("onMessageReceived:${message.messageId}")
    //SDK 阿里雲推送投遞到 FCM  的訊息會攜帶 payload 欄位，可以根據這個特徵判斷 FCM 此處收到的訊息來源
    //如存在 payload 內容，需將其傳遞給 SDK 進行處理
    val msg = message.getData()["payload"]
    if(msg.isNotEmpty()){
      LBWhaleApp.pushService.onThirdPushMsg(this,LBWhalePushService.ThirdPush.FCM, msg)
    }
  }
}
```

### 方式二：走 Broker 自己的渠道

Broker App 可以選擇自行接入第三方推送服務，業務訊息由 SDK 後端轉發至 Broker 後端，再由 Broker 後端推送到 Broker App 中。

在收到訊息時可呼叫 SDK 方法對訊息進行解析處理，SDK 提供 `LBWhaleApp.pushService.handleNotificationReceived` 方法用於解析訊息並展示應用內通知。

### 通知事件處理

#### 通知展示

應用內通知展示

- SDK 內建渠道：SDK 內部處理通知展示

- Broker 自有渠道：可在收到訊息後呼叫 `LBWhaleApp.pushService.handleNotificationReceived` 進行訊息處理，該方法會解析訊息內容並展示，注意該方法需要在 SDK 啟動後才能生效

應用外通知展示

- SDK 內建渠道：SDK 內部處理通知展示

- Broker 自有渠道：由 App 自行處理

#### 通知點選事件

應用內通知被點選

- SDK 內建渠道：SDK 內部處理通知點選事件

- Broker 自有渠道：如使用了 `LBWhaleApp.pushService.handleNotificationReceived` 方法處理訊息展示，則由 SDK 內部處理通知點選事件，否則需由 App 處理

應用外通知被點選

- SDK 內建渠道：透過 `LBWhalePushCallback` 回撥給 App 進行處理，收到此回撥時可選擇自行處理，也可以使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法處理該點選事件，該方法將會解析通知內容並進行相關頁面的跳轉。注意該方法需要在 SDK 啟動後才能生效

- Broker 自有渠道：可使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法處理點選事件，該方法將會解析通知內容並進行相關頁面的跳轉。注意該方法需要在 SDK 啟動後才能生效

## 實現 Callback 方法

```kotlin
LBWhaleApp.callback = object : LBWhaleAppCallback {
    //SDK 啟動成功時觸發，啟動成功後才可呼叫 LBWhaleApp 的相關方法
    override fun onLBWhaleAppStarted() {}

    //SDK 啟動失敗時觸發，請參考下方錯誤處理章節處理不同的錯誤型別
    override fun onLBWhaleAppStartFailed(error: Exception) {}

    //SDK 執行期間發生錯誤時觸發，請參考下方錯誤處理章節處理不同的錯誤型別
    override fun onLBWhaleAppRunInError(error: Exception) {}

    //SDK 自動續期後觸發；有效性與後續續期仍由 SDK 管理，Broker App 通常無需儲存或自行重新整理
    override fun onLBWhaleAppTokenChanged(token: String, refreshToken: String)

    //SDK 請求跳轉其他路由時觸發，可在此解析 url 跳轉至指定頁面，該 url 由 Broker 在後臺進行配置
    override fun onWhaleAppSdkOpenUrlRequested(url: String)
}
```

## 錯誤處理

```kotlin
sealed class LBWhaleAppError(message: String, cause: Throwable? = null) : Exception(message, cause) {
    //呼叫 startWithConfig 時如果必要引數為空將透過 onLBWhaleAppStartFailed 返回該異常，請檢查啟動引數內容
    class ConfigInvalid(field: String) : LBWhaleAppError("Invalid SDK config field: $field")

    //呼叫 SDK 方法時如果還未啟動 SDK 將會透過 onLBWhaleAppRunInError 返回該異常，請先啟動 SDK 再進行相關方法呼叫
    class NotInitialized() : LBWhaleAppError("SDK not initialized")

    //呼叫 startWithConfig 時如果傳入的引數經過後端校驗無效將透過 onLBWhaleAppStartFailed 返回該異常，請重新獲取相關 token 後再次啟動 SDK
    class InvalidAppKey : LBWhaleAppError("Invalid App Key provided")
    class InvalidAppSecret : LBWhaleAppError("Invalid App Secret provided")
    class InvalidToken() : LBWhaleAppError("Access token is invalid")
    class TokenExpired() : LBWhaleAppError("Access token has expired")

    //呼叫 startWithConfig 時如果傳入的 Refresh Token 無效將會在 onLBWhaleAppStartFailed 回撥中返回該異常，請重新獲取相關 token 後再次啟動 SDK
    //如在 onLBWhaleAppRunInError 回撥中收到該異常說明賬號在其他裝置進行了登入，請呼叫 logoutAndDestroy 登出 SDK，在重新獲取相關 token 後可再次啟動 SDK
    class RefreshTokenExpired() : LBWhaleAppError("Refresh token has expired")

    //SDK 啟動過程中獲取帳戶資訊失敗時透過 onLBWhaleAppStartFailed 返回該異常，可嘗試更換網路或直接重新啟動 SDK
    class SyncAccountStatusError : LBWhaleAppError("Sync account status error")

    //呼叫 startWithConfig 時如果發生其他網路請求錯誤將透過 onLBWhaleAppStartFailed 返回該異常，可嘗試更換網路或直接重新啟動 SDK
    class RequestFailed(message: String, val code: Int) : LBWhaleAppError("Request failed (code $code): $message")

    //呼叫 LBWhaleApp.pushService.handleNotificationOpened 處理訊息時如果檢測到非 LB 訊息則會返回該錯誤
    class UnrecognizedPushMessage(message: String = "Unrecognized push message format") : LBWhaleAppError(message)
}
```

如果是專案直接依賴了上述三方庫，**可將原版三方庫進行註釋**，使用 SDK 的定製版本即可。

如果是專案中的三方庫依賴了上述三方庫可透過下列程式碼進行排除

```groovy
implementation("xxxxxxxxxx") {
    exclude group: "xxxxx", module: "xxxxxx"
```
