## 1. 系统要求 {/* system-requirements */}

- **Min Android SDK**：24
- **Target Android SDK**：35
- **JDK**：17+
- **Kotlin**：1.8.22+
- **AGP**：8.5.2+
- **Gradle**：8.7+
- **架构支持**：arm64-v8a、armeabi-v7a
- **开发语言**：Java、Kotlin
- **Android Studio**：建议使用 2025.1.3+；低版本如出现构建不兼容请升级
- **其他**：不支持横屏展示。

## 2. 集成方式 {/* integration */}

下载 `LBWhaleAppSDK-XXX.zip (内含 aar 和 Demo)` 解压后，将 SDK 目录拷贝到 App 模块目录下（如 `app/` 目录），在 App 级别的 `build.gradle` 的 `plugins` 下方添加下列代码导入 SDK 配置文件。

```groovy
//下方路径示范是将 LBWhaleAppSDK 放置到 app 目录下，实际路径请根据 LBWhaleAppSDK 存放目录进行调整
apply from: "${project.file('LBWhaleAppSDK/whale-sdk-config.gradle')}"
```

### 2.1 ARouter 预编译优化（必须开启） {/* arouter-precompilation */}
SDK 内部使用 ARouter 进行路由，如**未开启**预编译优化将会**导致 init 方法耗时大幅度增加**，请在项目级别的 `build.gradle` 中添加如下插件：
```groovy
buildscript {
    dependencies {
        //路径请根据 LBWhaleAppSDK 实际存放位置调整
        classpath files('./../LBWhaleAppSDK/libs/lb-arouter-register-1.1.4.jar')
    }
}
```
在 App 级别的 `build.gradle` 的 `plugins` 中添加插件：
```groovy
plugins {
    id("com.longbridge.arouter")
}
```

### 2.2 Kapt 和 Databinding {/* kapt-and-data-binding */}
SDK 需要开启 Kapt 和 DataBinding 支持，如原有项目已开启可跳过该步骤，否则请按如下方式开启。

项目级别的 `build.gradle` 中添加下列代码
```groovy
apply plugin: 'kotlin-kapt'
```

App 级别的 `build.gradle` 中添加下列代码
```groovy
plugins {
    id("org.jetbrains.kotlin.kapt")
}
android {
    buildFeatures {
        viewBinding = true
        dataBinding = true
    }
}
```

### 2.3 R8 编译配置 {/* r8-configuration */}
打包 App 时，需要使用 R8 的兼容模式，否则会导致 SDK 内部出现异常。 在项目根目录的 `gradle.properties` 中进行如下配置。
```agsl
android.enableR8.fullMode=false
```

## 3. 初始化 SDK {/* initialize-sdk */}

在 `Application onCreate` 中调用 SDK 的 Init 方法进行必要资源的初始化准备，请在主线程调用该方法。

```kotlin
LBWhaleApp.init(application, debug = false)
```

`debug` 参数控制是否启用调试日志，默认为 `false`。

ps: 如未开启 ARouter 预编译优化，该方法耗时将会大幅度增加

## 4. 配置推送 {/* configure-push */}

推送的服务端渠道选择、云控制台配置以及标准消息结构，请参考[消息推送接入](/zh-cn/docs/message-push)。

### 4.1 方式一：走 SDK 内置渠道 {/* whale-managed-channel */}

SDK 内置阿里云推送，相关的业务推送可通过该渠道推送至客户端进行处理。

当收到推送时应用处于前台会显示**应用内通知**，当应用处于后台时则会显示**系统通知栏通知**。

如需使用内置阿里云推送功能请在 SDK 初始化之后调用下面方法， `LBWhaleApp.pushService.init(application, pushConfig)` 需要在主线程调用。
```kotlin
val notificationConfig = NotificationConfig(
    notificationIcon = R.mipmap.logo_notification,
    notificationSmallIcon = R.mipmap.lb_push_small_notification,
    notificationChannelId = channelId,
)

//创建推送配置
val pushConfig = LBWhalePushConfig.Builder()
    .appKey(BuildConfig.ALIYUN_PUSH_APP_KEY)
    .appSecret(BuildConfig.ALIYUN_PUSH_APP_SECRET)
    .disableMultiDevice(false) //可选，是否关闭多设备推送
    .notificationConfig(notificationConfig)
    .pushCallback(object : LBWhalePushCallback {
        override fun onNotificationOpened(title: String, summary: String, extMap: Map<String, String>) {
          //当通知栏通知被点击后触发该回调，需要在此判断 SDK 是否正在运行
          //然后调用 handleNotificationOpened 方法处理点击事件, 实现页面跳转
          if (LBWhaleApp.isStarted()) {
            LBWhaleApp.pushService.handleNotificationOpened(title, summary, extMap)
            return
          }
          //如 SDK 未启动，需启动 SDK 后再调用 handleNotificationOpened 进行处理
        }

        override fun onPushRegisterFailed(errorCode: String?, errorMessage: String?) {
          //推送通道注册失败时触发该回调，需要检查传入的阿里云配置参数是否正确
        }
    })
    .build()

//初始化推送服务
LBWhaleApp.pushService.init(this, pushConfig)
```

#### 4.1.1 厂商通道推送 {/* vendor-channel-push */}
SDK 内置的阿里云推送支持兼容第三方厂商通道，以达到提高推送到达率的效果。下方以 FCM 为例说明如何将 SDK 的业务消息发送至 FCM 消息。

初始化 Firebase 后上报 FCM Token 到 SDK

```kotlin
FirebaseApp.initializeApp(this, options)
FirebaseMessaging.getInstance().token.addOnCompleteListener { task ->
  if (task.isSuccessful) {
    val token = task.result
    //将 token 上报到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }
}
```

在 FirebaseMessagingService 中更新 Token 以及处理消息
```kotlin
class DemoFirebaseMessagingService : FirebaseMessagingService() {
  private val logger = SDKLogger.get(this::class)

  override fun onNewToken(token: String) {
    logger.i("onNewToken: $token")
    //将 token 上报到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }

  override fun onMessageReceived(message: RemoteMessage) {
    logger.i("onMessageReceived:${message.messageId}")
    //SDK 阿里云推送投递到 FCM  的消息会携带 payload 字段，可以根据这个特征判断 FCM 此处收到的消息来源
    //如存在 payload 内容，需将其传递给 SDK 进行处理
    val msg = message.getData()["payload"]
    if(msg.isNotEmpty()){
      LBWhaleApp.pushService.onThirdPushMsg(this,LBWhalePushService.ThirdPush.FCM, msg)
    }
  }
}
```

`repotThirdToken` 是当前 SDK 中该方法的真实拼写，请勿按 `reportThirdToken` 调用。

### 4.2 方式二：走 Broker 自有渠道 {/* broker-managed-channel */}

Broker App 可以选择自行接入第三方推送服务，业务消息由 Whale 转发至 Broker Server，再由 Broker Server 推送到 Broker App。
在收到消息时可调用 SDK 方法对消息进行解析处理，SDK 提供 `LBWhaleApp.pushService.handleNotificationReceived` 方法用于解析消息并展示应用内通知。

Broker App 既可以传入已解析的字段，也可以直接传入完整的标准消息 JSON：

```kotlin
//传入完整标准消息 JSON，SDK 自行解析 title、body 和 user_info
val result = LBWhaleApp.pushService.handleNotificationReceived(messageJson)

val clickResult = LBWhaleApp.pushService.handleNotificationOpened(messageJson)
```

字段重载接收 `title`、`summary` 以及完整的 `user_info` map。请勿自行拆平或重命名 `user_info` 中的字段。

两个方法均返回 `LBWhaleAppResult<Unit>`：

```kotlin
when (val result = LBWhaleApp.pushService.handleNotificationOpened(messageJson)) {
    is LBWhaleAppResult.Success -> Unit
    is LBWhaleAppResult.Error -> reportSanitized(result.cause)
}
```

`cause` 可能为 `NotInitialized`、`UnrecognizedPushMessage`、`MissingPushLink` 或 `InternalError`。

### 4.3 通知事件处理 {/* notification-event-handling */}
#### 4.3.1 通知展示 {/* notification-display */}
应用内通知展示
- SDK 内置渠道：SDK 内部处理通知展示
- Broker 自有渠道：可在收到消息后调用 `LBWhaleApp.pushService.handleNotificationReceived` 进行消息处理，该方法会解析消息内容并展示，注意该方法需要在 SDK 启动后才能生效

应用外通知展示
- SDK 内置渠道：SDK 内部处理通知展示
- Broker 自有渠道：由 App 自行处理

#### 4.3.2 通知点击事件 {/* notification-click-events */}
应用内通知被点击
- SDK 内置渠道：SDK 内部处理通知点击事件
- Broker 自有渠道：如使用了 `LBWhaleApp.pushService.handleNotificationReceived` 方法处理消息展示，则由 SDK 内部处理通知点击事件，否则需由 App 处理

应用外通知被点击
- SDK 内置渠道：通过 `LBWhalePushCallback` 回调给 App 进行处理，收到此回调时可选择自行处理，也可以使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法处理该点击事件，该方法将会解析通知内容并进行相关页面的跳转。注意该方法需要在 SDK 启动后才能生效
- Broker 自有渠道：可使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法处理点击事件，该方法将会解析通知内容并进行相关页面的跳转。注意该方法需要在 SDK 启动后才能生效

## 6. 实现 Callback 方法 {/* implement-callback */}

`LBWhaleApp.callback` 需要在调用 `startWithConfig` 之前赋值。

```kotlin
LBWhaleApp.callback = object : LBWhaleAppCallback {
    //SDK 启动成功时触发，启动成功后才可调用 LBWhaleApp 的相关方法
    override fun onLBWhaleAppStarted() {}

    //SDK 启动失败，错误类型请参考错误处理章节
    //可能的错误：InvalidConfig / InvalidAppKey / InvalidAppSecret / InvalidToken / TokenExpired / RefreshTokenExpired / RequestFailed / SyncAccountFailed
    override fun onLBWhaleAppStartFailed(error: Exception) {
        reportSanitized(error)
        when (error) {
            //凭证问题：引导用户重新登录，获取一组新的 token
            is LBWhaleAppError.InvalidToken,
            is LBWhaleAppError.TokenExpired,
            is LBWhaleAppError.RefreshTokenExpired -> redirectToLogin()
            //接入问题：检查项目交付的配置与启动参数
            is LBWhaleAppError.InvalidAppKey,
            is LBWhaleAppError.InvalidAppSecret,
            is LBWhaleAppError.InvalidConfig -> showIntegrationError(error)
            //可重试问题：检查网络后重新启动 SDK
            else -> showRetryableError(error)
        }
    }

    //运行期间发生错误，错误类型请参考下方错误处理
    //可能的错误：
    //  - RefreshTokenExpired: 运行期间后端（refresh token 过期），需要业务方处理 SDK 注销和重新启动
    //  - NotInitialized: 在 SDK 未启动（status != STARTED）时调用了 pushUrl / changeTheme / changeLanguage / changePriceColor 等需要先 start 的方法
    //注：refresh_token 失效时先触发 onLBWhaleAppRefreshTokenExpired；若未恢复，则会调用本方法抛出 RefreshTokenExpired 错误
    override fun onLBWhaleAppRunInError(error: Exception) {}

    //SDK 自动续期成功后的通知；凭证有效性和后续续期仍由 SDK 管理
    override fun onLBWhaleAppTokenChanged(token: String, refreshToken: String) {}

    //SDK 请求跳转其他路由时触发，可在此解析 URL 并交给 Broker App 路由；该 URL 由 Broker 在服务端配置
    override fun onWhaleAppSdkOpenUrlRequested(url: String) {}

    //token 与 refresh_token 均无法续期时触发。
    //默认实现会放弃重试，随后进入不可恢复的鉴权失败流程；Broker App 应销毁 SDK 并返回登出状态。
    //仅当项目另有约定并能取得一组全新的客户凭证时，才调用 resolver.resolve(newToken, newRefreshToken)。
    override fun onLBWhaleAppRefreshTokenExpired(resolver: LBWhaleAppRefreshTokenResolver) {
        resolver.resolve("", "")
    }
}
```

WhaleAppSDK 在内部完成凭证的校验与续期。Broker App 只需在启动时提供初始的 `token` 与 `refreshToken`，不需要调用 check token 或 refresh token 接口。

`onLBWhaleAppRefreshTokenExpired` 是常规续期失败后的兜底回调。上面的默认实现会放弃重试，随后运行时错误回调会抛出 `RefreshTokenExpired`，Broker App 据此销毁 SDK 并返回登出状态。仅当项目另有约定、且 Broker 能取得一组全新的客户凭证时，才通过 resolver 返回新凭证。

<Note>
正常情况下，WhaleAppSDK 自动完成 token 校验与续期，Broker App 不调用 check token 或 refresh token 接口。`onLBWhaleAppRefreshTokenExpired` 是极低概率异常的兜底扩展点，不应被实现为常规刷新流程。
</Note>

## 7. 实现 UICallback 方法（可选） {/* implement-ui-callback */}

`LBWhaleAppUICallback` 用于感知用户**进入 / 退出 SDK 页面**，与 `callback` 相互独立，按需注册。

- **进入 SDK**：打开第一个 SDK 页面时触发（存活 SDK 页面数 0 → 1）。
- **退出 SDK**：关闭所有 SDK 页面时触发（存活 SDK 页面数 1 → 0）。
- 判定按页面"是否存在"（onCreate / onDestroy），而非前后台可见性：App 切到后台但 SDK 页面仍存活，不算退出。
- SDK 销毁（`logoutAndDestroy`）时若仍停留在 SDK 页面，会补发一次退出回调。
- 两个回调均在主线程触发，可直接操作 UI。接口方法均有默认空实现，可只实现关心的方法。

```kotlin
LBWhaleApp.uiCallback = object : LBWhaleAppUICallback {
    //进入 SDK：打开第一个 SDK 页面
    override fun onLBWhaleAppEnterSdkPage() {}

    //退出 SDK：关闭所有 SDK 页面
    override fun onLBWhaleAppExitSdkPage() {}
}
```

## 9. 错误处理 {/* error-handling */}

| `LBWhaleAppError` | 触发场景 | 建议处理 |
| --- | --- | --- |
| `InvalidConfig(field)` | 启动时必填字段为空 | 修正接入配置后重新启动 |
| `NotInitialized` | 启动成功前调用了依赖 SDK 状态的方法 | 等待 `onLBWhaleAppStarted` 后再调用 |
| `SyncAccountFailed` | 启动过程中同步账户信息失败 | 检查网络后重新启动 SDK |
| `InvalidAppKey` / `InvalidAppSecret` | 项目凭证被服务端拒绝 | 核对项目交付的配置 |
| `InvalidToken` / `TokenExpired` | 传入的初始客户凭证无效 | 重新获取一组新的登录会话 |
| `RefreshTokenExpired` | 会话无法续期 | 销毁 SDK 并返回登出状态 |
| `RequestFailed(message, code)` | 其他网络请求失败 | 记录脱敏后的 code 与 message，按项目重试策略处理 |
| `UnrecognizedPushMessage` | 消息不是 Whale 推送消息 | 交由 Broker App 自行处理 |
| `MissingPushLink` | 是 Whale 消息但解析后无跳转路由 | 不执行跳转，上报脱敏后的元信息 |
| `InternalError(cause)` | 路由或 SDK 操作中的未预期异常 | 通过项目监控上报脱敏后的堆栈 |

```kotlin
sealed class LBWhaleAppError(message: String, cause: Throwable? = null) : Exception(message, cause) {
    //SDK Configuration Errors
    //调用 startWithConfig 时如果必要参数为空将通过 onLBWhaleAppStartFailed 返回该异常，请检查启动参数内容
    class InvalidConfig(field: String) : LBWhaleAppError("Invalid SDK config field: $field")

    //调用 SDK 方法时如果还未启动 SDK 将会通过 onLBWhaleAppRunInError 返回该异常，请先启动 SDK 再进行相关方法调用
    object NotInitialized : LBWhaleAppError("SDK not initialized")

    //SDK 启动过程中获取账户信息失败时通过 onLBWhaleAppStartFailed 返回该异常，可尝试更换网络或直接重新启动 SDK
    object SyncAccountFailed : LBWhaleAppError("Sync account status error")

    //Authentication Errors
    //调用 startWithConfig 时如果传入的参数无效将通过 onLBWhaleAppStartFailed 返回该异常
    object InvalidAppKey : LBWhaleAppError("Invalid App Key provided")
    object InvalidAppSecret : LBWhaleAppError("Invalid App Secret provided")
    object InvalidToken : LBWhaleAppError("Access token is invalid")
    object TokenExpired : LBWhaleAppError("Access token has expired")

    //调用 startWithConfig 时如果传入的 Refresh Token 无效将会在 onLBWhaleAppStartFailed 回调中返回该异常，请重新获取相关 token 后再次启动 SDK
    //如在 onLBWhaleAppRunInError 回调中收到该异常说明账号在其他设备进行了登录，请调用 logoutAndDestroy 登出 SDK，在重新获取相关 token 后可再次启动 SDK
    object RefreshTokenExpired : LBWhaleAppError("Refresh token has expired")

    //Network Request Errors
    //调用 startWithConfig 时如果发生其他网络请求错误将通过 onLBWhaleAppStartFailed 返回该异常，可尝试更换网络或直接重新启动 SDK
    class RequestFailed(message: String, val code: Int) : LBWhaleAppError("Request failed (code $code): $message")

    //Push Message Errors
    //调用 LBWhaleApp.pushService.handleNotificationOpened 处理消息时如果检测到非 LB 消息则会返回该错误
    object UnrecognizedPushMessage : LBWhaleAppError("Unrecognized push message format")

    //调用 LBWhaleApp.pushService.handleNotificationOpened 时，LB 推送消息但解析后跳转 link 为空将返回该错误
    object MissingPushLink : LBWhaleAppError("Push message missing link")

    //SDK 内部未预期异常的统一包装，cause 字段保留原始 Throwable，可用于上报堆栈
    class InternalError(cause: Throwable, message: String? = cause.message)
        : LBWhaleAppError(message ?: "Internal SDK error", cause)
}
```

### SDK 内部定制第三方库 {/* customized-third-party-libraries */}

| `com.github.barteksc:android-pdf-viewer` | [AndroidPdfViewerV2](https://github.com/barteksc/AndroidPdfViewerV2)、[PdfiumAndroid](https://github.com/meganz/PdfiumAndroid) |

| `com.contrarywind:Android-PickerView` | [Android-PickerView](https://github.com/Bigkoo/Android-PickerView) |
| `skin.support:skin-support` | [Android-skin-support](https://github.com/ximsfei/Android-skin-support) |
| `com.github.tbruyelle:rxpermissions` | [RxPermissions](https://github.com/tbruyelle/RxPermissions) |

```groovy
implementation("xxxxxxxxxx") {
```

### 11.2 LBWhalePushService {/* lb-whale-push-service */}
通过 LBWhaleApp.pushService 获取，用于管理推送服务相关能力
```kotlin
//初始化推送服务（需在主线程调用）
fun init(application: Application, pushConfig: LBWhalePushConfig)

//获取推送服务设备 ID
fun getPushDeviceId(): String

//上报第三方厂商通道（如 FCM）的 Token 到 SDK
fun repotThirdToken(context: Context, thirdPush: ThirdPush, token: String)

//将第三方厂商通道收到的消息透传给 SDK 进行解析处理
fun onThirdPushMsg(context: Context, thirdPush: ThirdPush, msg: String?)

//解析通知消息并展示应用内通知（Broker 自有渠道收到消息后调用）
//返回值为 LBWhaleAppResult<Unit>，LBWhaleAppResult.Error 时 cause 可能为 NotInitialized（SDK 未启动）/ UnrecognizedPushMessage（非 LB 推送消息）/ InternalError（内部未预期异常）
fun handleNotificationReceived(
    title: String,
    summary: String,
    extraMap: Map<String, String>,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//直接接收完整标准消息 JSON；SDK 解析 title、body 和 user_info
fun handleNotificationReceived(
    json: String,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//处理通知栏通知点击事件
//返回 LBWhaleAppResult<Unit>，LBWhaleAppResult.Error 时 cause 可能为：
//  - LBWhaleAppError.NotInitialized          : SDK 未启动（应先调用 LBWhaleApp.startWithConfig）
//  - LBWhaleAppError.UnrecognizedPushMessage : extMap 中缺少 lb_push_from 字段，说明该消息并非来自 LB 推送体系
//  - LBWhaleAppError.MissingPushLink         : LB 推送消息但解析后跳转 link 为空
//  - LBWhaleAppError.InternalError           : 路由 / 埋点等过程中抛出的未预期异常的兜底包装
fun handleNotificationOpened(
    title: String,
    summary: String,
    extMap: Map<String, String>,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//直接接收完整标准消息 JSON，并处理通知点击路由
fun handleNotificationOpened(
    json: String,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//路由回调，SDK 完成通知解析后回传最终跳转的 URL
fun interface NotificationRouterCallback {
    fun onRouter(url: String)
}

//当前支持的第三方厂商通道
enum class ThirdPush { FCM }
```

完整 JSON 重载会先读取 `title`、`body` 和 `user_info`，再调用对应的字段重载。两个字段重载均通过 `@JvmOverloads` 为 Java 生成重载方法。

`handleNotificationReceived` 和 `handleNotificationOpened` 返回 `LBWhaleAppResult<Unit>`。成功时为 `LBWhaleAppResult.Success`；失败时为 `LBWhaleAppResult.Error`，通过 `cause` 读取具体的 `LBWhaleAppError`。Broker 自有渠道应优先传入 [标准消息结构](/zh-cn/docs/message-push#http-convention)，不要自行拆改 `user_info`。

```kotlin
sealed class LBWhaleAppResult<out T> {
    data class Success<T>(val value: T) : LBWhaleAppResult<T>()
    data class Error(val cause: Throwable) : LBWhaleAppResult<Nothing>()

    val isSuccess: Boolean
    val isError: Boolean

    companion object {
        @JvmField val Ok: LBWhaleAppResult<Unit>
    }
}
```

Kotlin 侧提供 `onSuccess`、`onError`、`map`、`fold`、`getOrNull`、`getOrElse` 等扩展函数。

### 11.12 LBWhaleAppCallback - SDK 事件回调 {/* sdk-event-callback */}

```kotlin
interface LBWhaleAppCallback {
```

### 11.13 LBWhalePushCallback - 推送事件回调 {/* push-event-callback */}
```kotlin
interface LBWhalePushCallback {
    /**
     * 用户点击通知栏通知时触发此回调。
     * 参数：title 通知标题、summary 通知摘要、extMap 阿里云透传的扩展字段。

     * 未启动则需先启动 SDK 后再处理。

    fun onNotificationOpened(title: String, summary: String, extMap: Map<String, String>)

     * 推送通道（阿里云）注册失败时回调，对应 iOS 的 NotificationErrorPushStartFailed。

    fun onPushRegisterFailed(errorCode: String?, errorMessage: String?) {}
```
