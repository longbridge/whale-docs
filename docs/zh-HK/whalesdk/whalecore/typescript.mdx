TypeScript 套件讓 WhaleCore 在瀏覽器裡執行。引擎編譯為 WebAssembly，套件在其上提供類型化的 ES 模組，涵蓋 HTTP 透傳、行情、自選股、資產和訂單。Broker App 負責全部界面，套件負責工作階段、連線與數據。

## 系統要求與安裝 {/* requirements-and-installation */}

| 要求 | 說明 |
| --- | --- |
| 執行環境 | 支援 WebAssembly、ES 模組和 `WebSocket` 的瀏覽器 |
| 打包工具 | 能解析 `exports` 子路徑和 `import.meta.url` 的打包工具，如 Vite、esbuild、webpack 5、Rspack 或 Parcel 2 |
| TypeScript | 可選。類型宣告隨套件一起分發；若報出 `Symbol.dispose` 錯誤，請在 `lib` 中加入 `ESNext.Disposable` |
| Node.js | 不是執行目標。引擎需要 `window`、`localStorage` 和 `WebSocket`，且沒有伺服器端建置產物 |

本套件不發佈到公開 registry。壓縮檔由 Whale 專案團隊私下交付，而且**每份產物只對應一個租戶** —— 簽名密鑰編譯進了 WebAssembly 二進位檔案。請安裝收到的那份檔案，並放在建置流程能讀取的位置。

套件會帶入一個執行時依賴 `protobufjs`，因為行情載荷是 Protobuf。只用到 `initialize` 和 `request` 的建置產物不會包含解碼器。

每個模組都是獨立子路徑：

```ts
import { initialize, request } from 'whalecore-web';
import { quotes, SubType } from 'whalecore-web/quotes';
import { Watchlist } from 'whalecore-web/watchlist';
import { Portfolio } from 'whalecore-web/portfolio';
import { Orders } from 'whalecore-web/orders';
```

## 託管 WebAssembly 檔案 {/* host-the-wasm-binary */}

`engine_bg.wasm` 在執行時按 URL 取得，任何打包工具都不會內嵌它。請把套件內的 `engine/pkg/engine_bg.wasm` 複製到建置產物旁邊，並以 `Content-Type: application/wasm` 提供。Vite 用 `publicDir` 完成這次複製，webpack 用 `CopyPlugin`。定位套件路徑請用 `require.resolve`，不要寫死 `node_modules` 路徑，因為 `file:` 連結和 pnpm 儲存都是符號連結。

引擎會在自己的 JavaScript 模組旁邊尋找該檔案。當打包工具改變產物位置，或者二進位檔案由 CDN 提供時，請在 `initialize` 之前明確載入：

```ts
import { load, initialize } from 'whalecore-web';

await load('https://cdn.example.com/engine_bg.wasm');
await initialize({ /* … */ });
```

`load` 是冪等的，可以安全重試。宿主不調用時，`initialize` 會代為調用。

### 壓縮檔案 {/* compress-the-binary */}

發佈的二進位檔案已經做過體積最佳化，餘下的成本在傳輸：Brotli quality 11 大約能壓掉 69%，而 `gzip -9` 只到 58% 左右。請在建置期壓縮，而不是每次請求都壓縮 —— 用 `vite-plugin-compression`、`compression-webpack-plugin` 或打包器自帶的方案都可以。

<Warning>
  壓縮後的檔案必須同時帶上 `Content-Encoding: br` 和 `Content-Type: application/wasm`。載入器使用 `WebAssembly.instantiateStreaming`，它要求這個 MIME 類型；換成其他值，瀏覽器會先把整個模組緩衝完再編譯。部分 CDN 的可壓縮類型清單裡沒有 `application/wasm`，會靜默地把檔案按未壓縮交付。
</Warning>

## 初始化 {/* initialize */}

```ts
import { initialize } from 'whalecore-web';

await initialize({
  appId: 'com.example.app',
  accountChannel: 'lb',
  deviceID: await deviceID(),
  language: 'zh-HK',
  version: '1.0.0',
  binding: {
    renewToken: () => fetchCredentials(),
    // '000000' is the paper channel's password; real channels take their own
    renewTradeToken: (accountChannel) => exchangeTradeToken(accountChannel, '000000'),
  },
  logger: (message, fields) => console.debug(fields.get('level'), message),
});
```

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| `binding` | 是 | 憑證兜底回呼，見 [Token 與交易鑑權](/zh-hk/whalesdk/whalecore/typescript#tokens-and-trade-authentication)。缺少時拋出 `no binding` |
| `appId` | — | 應用標識，同時作為 `x-app-id` 發送 |
| `accountChannel` | — | 工作階段標識，並作為 `account-channel` 請求頭附加到所有請求 |
| `deviceID` | — | 作為 `x-device-id` 發送，見[裝置標識](/zh-hk/whalesdk/whalecore/typescript#device-identifier) |
| `defaultHeaders` | — | 附加到所有請求的額外請求頭 |
| `language` | — | `en`、`zh-CN` 或 `zh-HK`。其他取值會回落到 `en` |
| `version` / `build` | — | 以 `x-application-version` 和 `x-application-build` 上報 |
| `logger` | — | 引擎日誌；`fields` 攜帶 `level` 與 tracing 元數據 |

引擎會忽略無法識別的鍵，所以寫錯欄位名不會報錯，只是不生效。請讓 `EngineConfig` 類型來檢查這個物件。

`initialize` 每次頁面載入只調用一次。第二次調用會重建 HTTP 用戶端，但不會關閉上一條行情長連線，而 `appId`、`version` 和 `build` 仍保留首次調用的取值。切換帳戶不需要再次調用，見[生命週期](/zh-hk/whalesdk/whalecore/typescript#lifecycle)。

### 裝置標識 {/* device-identifier */}

`deviceID` 會成為 `x-device-id` 請求頭。瀏覽器不提供裝置序號，所以這個值由 Broker App 自行產生並自行保存，目標是「同一台機器上的同一個瀏覽器長期保持同一個值」。用 `crypto.randomUUID` 同時寫入 `localStorage` 和長期有效的第一方 cookie 就夠了 —— 兩者被清理的時機不同，可以互相復原；再疊一個指紋庫，還能在兩層都被清空後重新算出接近相同的值。

- 先讀儲存，只有每一層都為空時才產生，且不要用新算出的值覆蓋已經存下來的值。請每次造訪都重新寫入，讓被清掉的那一層自動補回。
- 在 `initialize` 之前把值取到，因為引擎一啟動就會發出請求。
- 保持取值不透明。它會隨請求頭進入伺服器端日誌，所以請用哈希或 UUID，不要放入任何可識別到個人的資訊。

不傳 `deviceID` 也是允許的：請求頭不出現，引擎不會替你產生替代值。

### 客戶工作階段 {/* client-session */}

存取令牌存放在引擎工作階段中，在瀏覽器裡就是不帶前綴的 `localStorage`；設定裡沒有 token 欄位。只要實作 [`binding.renewToken`](/zh-hk/whalesdk/whalecore/typescript#tokens-and-trade-authentication) 就夠了：冷工作階段下第一個鑑權請求不帶 token 發出、被伺服器拒絕，引擎隨即呼叫 `renewToken`、存下回傳的一對令牌並重放該請求。

在 `initialize` 之前把 Broker 登入流程取得的 `token` 與 `refresh_token` 預先寫入，是一項可選最佳化：省掉那次被拒的往返。請勿把憑證或完整 token 寫入日誌。

```ts
const { token, refresh_token } = await fetchCredentials();
localStorage.setItem('token', token);
localStorage.setItem('refresh_token', refresh_token);
await initialize({ /* … */ });
```

交易令牌按帳戶渠道單獨存放，由引擎自行寫入。

## Token 與交易鑑權 {/* tokens-and-trade-authentication */}

引擎會自行完成每個請求的鑑權，並用手上的 refresh token 為已過期的存取令牌續期。`binding` 覆蓋它唯一無法獨自處理的情況：refresh token 也沒有了。

```ts
const binding = {
  // 工作階段中沒有 refresh_token 且請求返回 401003 時調用
  async renewToken() {
    const res = await fetch('/session/login', { method: 'POST' });
    return (await res.json()).credentials; // { token, refresh_token }
  },
  // 工作階段中沒有交易 refresh token 且請求返回 402000 時帶上帳戶渠道調用
  renewTradeToken(accountChannel) {
    // '000000' is only lb_papertrading's password; supply the real one per channel
    return exchangeTradeToken(accountChannel, '000000');
  },
};
```

請返回新的一對憑證。引擎會保存兩者，用 refresh token 換取新的存取令牌，並重放原來的請求，因此 `request` 的調用方察覺不到這一次往返。拋出例外、reject 或返回結構不符的值，都表示無法續期：引擎停止嘗試，原始的 `ApiError` 拋給調用方，客戶由此回到登入頁。兩個回呼都可能在多個請求同時收到 `401` 時並行觸發；引擎會把續期收斂為一次，所以請保持回呼輕量，也不要自行加鎖。

<Note>
  首次取得交易令牌由 `exchangeTradeToken(accountChannel, password)` 完成：它用該帳戶的交易密碼換回 `{ token, refresh_token }`，由引擎按渠道存。密碼按用戶輸入的原文傳入。按上面接進 `renewTradeToken` 即可。
</Note>

## 生命週期 {/* lifecycle */}

| 任務 | 做法 |
| --- | --- |
| 初始化 | `await initialize(config)`，每次頁面載入一次 |
| 前景與背景 | 無需調用。瀏覽器會節流計時器，引擎自行重連 |
| 同租戶內切換帳戶 | `portfolio.logout()`，寫入新的 `token` 與 `refresh_token`，`portfolio.login()`，重新發現帳戶，重新訂閱 |
| 切換租戶 | 載入為該租戶建置的產物 |
| 登出 | `portfolio.logout()` 清除 `token` 與 `refresh_token`，並卸載全部引擎元件 |
| 銷毀 | 重新載入頁面。沒有明確的銷毀調用 |

### 發現帳戶 {/* discover-accounts */}

登入後帳戶清單已經在引擎裡，所以從 SDK 讀取，而不是自己呼叫那個接口。`user` 原樣回傳引擎載荷，欄位是 `snake_case`，與資產視圖同一套約定。

```ts
import { onUserChange, user } from 'whalecore-web/portfolio';

const off = onUserChange(() => {
  const accounts = user()?.accounts ?? [];
  portfolio.watch(accounts.map((a) => ({ accountChannel: a.account_channel!, aaid: a.aaid! })));
});
```

使用者匿名時 `user` 回傳 `undefined`，並在此時觸發拉取，所以第一次呼叫通常仍回傳 `undefined`，資料隨後經 `onUserChange` 到達。不要在渲染迴圈裡輪詢 `user`：載荷到手後不會重複拉取，但第一次拉取回傳前的每次呼叫都會再發一輪使用者請求。請等變更通知，或快取已讀到的值。

帳戶條目的欄位以型別宣告為準。其中兩個容易混淆：`account_open` 與 `deposit` 是彼此獨立的事實，因此「已開戶但沒有資金」和「從未開戶」可以區分；`t_pwd` 表示該帳戶是否已設定交易密碼。

同一份載荷也餵給訂單模組：

```ts
const orders = new Orders({ accountChannel: 'lb', account: () => accountFactsOf(user(), 'lb') });
```

`aaid` 傳錯時資產模組會靜默失敗，既沒有視圖也沒有錯誤，這正是應當讀取清單而非自行拼裝的原因。

## 行情 {/* quotes */}

行情倉庫把引擎推送物化成完整的 `Stock` 快照。啟動一次，掛載頁面需要的標的，然後訂閱。

```ts
import { quotes, SubType, Change, Counter, compare } from 'whalecore-web/quotes';

quotes.start();
await quotes.mount('watchlist', ['ST/HK/700', 'ST/US/AAPL'], SubType.List | SubType.Depth);

const off = quotes.watch('ST/HK/700', (stock, flags) => {
  if (flags & Change.Price) render(stock.trading);
  if (flags & Change.Depth) renderBook(stock.depths);
});
```

- 標的以 counter 為主鍵，寫作 `ST/HK/700` 而不是 `00700.HK`。`Counter.parse` 返回補齊後的顯示代碼，以及 `isStock`、`isOption` 這類品種判斷。
- `mount(id, counters, subtypes)` 是宣告式的：該標識持有的正是傳入的那批標的，從列表中移除的標的會被退訂。請給每個頁面獨立的標識。
- `SubType` 是位標記，取值有 `List`、`Detail`、`Depth`、`Trade`、`Broker`、`PreTrade`、`PostTrade`、`NightTrade`、`TotalView` 和 `TotalViewBrief`，另有組合值 `Trades`。預設值是 `SubType.List`，它已經包含盤前、盤後與夜盤價格。
- 價格是 `Decimal`，即字串，以保留伺服器精度。在 JavaScript 裡 `'9' > '10'` 為 `true`，所以請用 `compare` 比較。`changePercent`、`marketCap`、`turnoverRate` 和 `greeks` 等衍生指標返回 `number`，適合排序與粗略顯示，不適合金額計算。
- `version(counter)` 與 `subscribe(listener)` 的形狀與 `useSyncExternalStore` 的要求一致。

行情變動頻繁。請用 `requestAnimationFrame` 批量渲染，不要逐條響應。

## 自選股 {/* watchlist */}

```ts
import { Watchlist, WatchlistChange, SortField } from 'whalecore-web/watchlist';

const watchlist = new Watchlist({ accountChannel: 'lb', aaid });
await watchlist.refresh({ subscribe: true });

watchlist.subscribe((flags) => {
  if (flags & WatchlistChange.Groups) renderTabs(watchlist.groups());
  if (flags & WatchlistChange.Order) renderList(watchlist.counters());
});

watchlist.setGroup(groupId, { field: SortField.ChangePercent, asc: false });
await watchlist.addStocks(['ST/HK/700'], [groupId]);
await watchlist.tie(['ST/HK/700']);
```

`groups`、`counters`、`stockInfo`、`fundInfo`、`tied`、`sort` 和 `version` 都是對本機快取的同步讀取。寫操作是非同步的，並與伺服器對帳。排序在本機基於行情倉庫完成，所以何時重排由宿主決定，請在批次處理的影格裡調用 `resort`。

跨裝置同步預設開啟：其他裝置改動分組時，實例會自行重新整理。傳 `sync: false` 可以關閉；建立多個實例時請給出不同的 `id`。

## 資產 {/* portfolio */}

資產由引擎計算，包含匯率、成本價、盈虧與顯示格式。本模組是帶按帳戶快取的類型化傳輸層：宣告要訂閱的帳戶，引擎每影格推送一份完整視圖快照。

```ts
import { Portfolio } from 'whalecore-web/portfolio';

const portfolio = Portfolio.shared();
portfolio.login();
portfolio.setUser({ currency: 'HKD', costType: 'dilute' });
portfolio.watch([{ accountChannel: 'lb', aaid }]);

portfolio.subscribe((event) => {
  if (event.kind === 'view') {
    render(event.view.overview.total_fortune, event.view.stock_hold.HK);
  } else {
    console.log(event.error);
  }
});
```

| 方法 | 作用 |
| --- | --- |
| `login()` / `logout()` | 通知工作階段發生變化。`logout` 同時清除令牌與元件 |
| `setUser(settings)` | 幣種與會員口徑：`currency`、`costType`、`usePrePostPrice`、`useOvernightPrice`、`useOptionExtendPrice` |
| `watch(accounts)` | 宣告式，本次列表取代上一次。現金明細與行情驅動重算保持開啟，且每次調用都會重新拉取。重新整理同一批帳戶請用 `refresh` |
| `refresh(aaid?)` | 強制重新拉取單個帳戶或全部帳戶 |
| `unwatch()` | 停止全部訂閱並清空快取 |
| `get(aaid)` / `aaids()` / `version()` | 對快取的同步讀取 |

關於視圖有三點需要注意：

- 欄位是 `snake_case`，而入參是 camelCase，因為載荷是原樣透傳的。
- 取值已按顯示格式處理。金額是 `Decimal` 字串，百分比自帶 `%`，如 `"12.34%"`，不要再乘 100；取不到的數值是字面值 `'--'`；期權希臘字母是 JSON number，同樣可能是 `'--'`。
- 首個影格可能不完整。隨著引擎的取數陸續落地，各分區會在最初幾個影格內補齊，現金明細與資產分佈通常晚一點到達。某個分區沒有出現在首個影格，並不表示引擎不提供它。

多數失敗按設計是靜默的：`aaid` 傳錯、網絡錯誤、`5xx`，或者任何未被映射的業務碼，都不會產生事件，與「仍在載入」無法區分。六個業務碼映射為四種類型：`401003`、`401004`、`401005` 和 `401008` 對應 `tokenRequired`；`402000` 和 `402001` 對應 `tradeTokenRequired`，並攜帶 `accountChannel`；另有 `tradeAccountLimited` 與 `unknown`。需要「載入失敗」狀態時，請在 `watch` 之後自行加逾時。

## 訂單 {/* orders */}

訂單模組涵蓋當日訂單、歷史訂單、下單、改單、撤單、下單前置檢核與訂單預覽。每個方法都要求交易鑑權，請先實作 `renewTradeToken`，見 [Token 與交易鑑權](/zh-hk/whalesdk/whalecore/typescript#tokens-and-trade-authentication)。沒有它，每次呼叫都會以業務碼 `402000` 失敗。

```ts
import { Orders } from 'whalecore-web/orders';

const orders = new Orders({ accountChannel: 'lb' });

await orders.refresh();
orders.subscribe(() => render(orders.today()));
```

`refresh` 拉取當日訂單並開始接收訂單推送，此後訂單變更會自行合併進快取。讀取路徑透過 `today`、`open`、`get` 和 `version` 同步回傳，因此 `subscribe` 與 `version` 可直接配合 `useSyncExternalStore`。

| 方法 | 作用 |
| --- | --- |
| `refresh(filter?)` | 重新拉取當日訂單並開始合併推送 |
| `history(page, limit, filter?)` | 分頁歷史，帶 `hasMore` |
| `detail(orderId)` | 單筆訂單，含成交流水、費用明細與附帶單 |
| `submit(order)` | 下單並回傳 `orderId` |
| `replace(request)` | 修改委託價、數量、備註或條件單欄位 |
| `cancel(orderId)` / `batchCancel(request)` | 撤單，可按單筆、按標的與方向，或按訂單 ID 清單 |
| `orderInfo`、`tradable`、`constraints` | 單一標的的交易規則與渠道能力 |
| `estimateBuyLimit`、`estimatedCost`、`tradeDetail` | 可買力、費用預估，以及標的維度的現金與持倉 |

訂單狀態歸一為 15 個取值，用 `isTerminal`、`isCancellable`、`isModifiable` 讀取，`rawStatus` 保留服務端原始字串。金額與數量都是 `Decimal` 字串，同一子路徑匯出 `arith` 用於定點運算。

### 先檢核，再下單 {/* order-validation */}

`SubmitOrder` 按 `orderType` 做判別聯合，因此「限價單不帶委託價」這種組合根本編譯不過。請從下單頁建構 `OrderIntent`，讓檢核產出請求物件：

```ts
import { newRequestId, type OrderIntent } from 'whalecore-web/orders';

const intent: OrderIntent = {
  counterId: 'ST/US/AAPL',
  side: 'buy',
  orderType: 'LO',
  clientRequestId: newRequestId(),
  price: '150.25',
  quantity: '100',
  validity: { tif: 'day' },
  sessionPreference: 'rthOnly',
};

const draft = await orders.validate(intent, 'draft');
setSubmitEnabled(draft.passed);

const checked = await orders.validate(intent, 'submission');
if (checked.passed && checked.request) {
  await orders.submit(checked.request);
}
```

每條 issue 都帶穩定的 `code`、`rule`、要高亮的 `field`，以及已本地化的 `reason`。`draft` 檔涵蓋 Client 邊填邊改就能修正的部分；`submission` 檔追加帳戶與資格門禁，通過時回傳已物化的 `request`。進入下單頁前呼叫 `checkTradability`，渲染訂單類型選擇器用 `constraints` —— 它列出的類型不會再因「類型不支援」被拒。

`clientRequestId` 是幂等鍵。重試同一筆訂單必須沿用同一個值，新一筆訂單用 `newRequestId` 換新值，服務端按它去重。

### 訂單預覽 {/* order-preview */}

`preview` 取齊下單頁需要的訂單、費用、成本、保證金與匯率來源，回傳算好的數：訂單總額、費用、融資、佔用購買力、成交後成本、現金與保證金變動，以及風險提示。

```ts
const result = await orders.preview(intent, { marketReferencePrice: quote.lastDone });
render(result.orderTotal, result.fees.total, result.riskHint);
```

模組不讀行情，因此行情事實經 `context` 傳入：市價單的參考價，以及期權的 `optionDirection` 與 `optionStrikePrice`。結果裡的 `undefined` 表示**結構上不適用**（例如賣出沒有融資），而不是資料缺失。

`preview` 需要帳戶類型 —— 現金戶與融資戶的預覽差半屏 —— 所以建構模組時請提供帳戶事實。`accountFactsOf` 對映 [`user`](/zh-hk/whalesdk/whalecore/typescript#discover-accounts) 回傳的載荷：

```ts
const orders = new Orders({
  accountChannel: 'lb',
  account: () => accountFactsOf(user(), 'lb'),
  language: () => 'zh-HK',
});
```

不提供帳戶事實時，`preview` 拋出 kind 為 `accountUnavailable` 的 `PreviewError`，而檢核裡那三條帳戶門禁會靜默放行而不是攔住。自行取數的宿主可以繞開該方法，直接呼叫匯出的純函式 `compute(fields)`，它一行網路都不打。

### 邊界 {/* order-boundaries */}

- 渠道能力並不一致。`orderInfo` 會告知某個標的接受的訂單類型與附帶單類型，而渠道仍可能拒掉這些欄位看起來允許的請求。在向 Client 開放批量撤單與附帶單之前，請在你啟用的每個渠道上分別驗證。
- `submit` 被拒**不能**證明請求沒有觸達服務端，附帶單失敗時主單也可能已經生效。重試前先重新拉取當日訂單，並沿用同一個 `clientRequestId`，避免一次重試變成第二筆訂單。
- 訂單資料不落儲存。快取只在記憶體中，`dispose` 會清空它並移除推送監聽。

## 連線狀態 {/* connection-state */}

引擎維護兩條 WebSocket。`quote` 通道承載行情數據，`text` 通道承載業務推送，如訂單變化、資產訊號和自選股主題。兩條通道各自獨立建連與重連。

```ts
import { readyState, isOpen, onConnectionChange, ReadyState } from 'whalecore-web';

readyState('quote'); // ReadyState.Open
isOpen(); // 兩條通道都已連線

const off = onConnectionChange(({ channel, state }) => {
  console.log(channel, ReadyState[state]); // 枚舉帶反向映射
  setOnline(isOpen());
});
```

不傳通道時，`readyState` 會把兩條歸一，取其中較差的那個：兩條都是 `Open` 才得到 `Open`，任一為 `Closed` 時以 `Closed` 為準，其次是 `Reconnecting`，再次是 `Opening`。事件本身是分通道的，界面顯示合併狀態時，請在回呼裡調用 `readyState`。兩個調用都是同步的，開銷很小，且這一層不做快取，所以監聽器掛載得晚也不會與實際狀態不一致。在 React 中，`useSyncExternalStore(onConnectionChange, () => readyState('quote'))` 得到的是穩定快照。

有兩種行為需要處理：

- 首次建連之前狀態是 `Reconnecting` 而不是 `Closed`，因為這是兩條通道的初始值。「從未連線」與「斷開後正在重連」共用同一個取值，所以文案不要寫成連線已經失去。
- 同一個通道與狀態會重複出現。握手失敗會重試，每次嘗試都會再報一次 `Opening`。這裡不做去重：請與上一次的值比較，或者交給 React 比較快照。

## 通用 HTTP 請求 {/* general-http-requests */}

調用尚未類型化封裝的 [TradingAPI](/zh-hk/trading-api/overview) 接口時使用 `request`。簽名、鑑權、重試與令牌續期依然生效。

```ts
import { request, ApiError } from 'whalecore-web';

try {
  const { data, headers } = await request<MemberInfo>('GET', '/v2/member/info');
  console.log(data.member, headers['x-trace-id']);
} catch (err) {
  if (err instanceof ApiError && err.info.kind === 'http') {
    console.warn(err.info.status, err.info.code);
  }
}
```

| 選項 | 行為 |
| --- | --- |
| `params` | 追加為查詢字串。嵌套物件展開為 `a[b]=c`，陣列重複同一個鍵，`null` 值會被丟棄 |
| `data` | JSON 請求體 |
| `headers` | 覆蓋合併到 `initialize` 的預設請求頭之上 |
| `timeout` | 毫秒。為 `0` 或不傳時使用引擎預設的 15 秒 |
| `singleflight` | 對並行的相同請求去重。`GET`、`HEAD` 和 `OPTIONS` 預設開啟；其餘調用方以 `ErrorCode.DEDUPLICATED` 失敗 |

泛型參數只是類型斷言，執行時不做檢查。

### 錯誤 {/* errors */}

`ApiError.info` 是按 `kind` 區分的可辨識聯合：

| `kind` | 含義 | 主要欄位 |
| --- | --- | --- |
| `http` | 伺服器返回了錯誤信封 | `status`、`code`、`message`、`detail`、`traceId`、`headers`、`data` |
| `request` | 傳輸失敗，包含網絡、CORS 與逾時 | `code`、`traceId` |
| `websocket` | 推送通道錯誤 | `code`、`status`、`message` |
| `other` | 其他情況 | `code`、`error` |

HTTP 狀態碼不等於業務碼。令牌失效時返回的是 HTTP `400`，業務碼為 `401004`。請按 `info.code` 分支，而不是 `info.status`。表示工作階段已結束的業務碼是 `401003`、`401004`、`401005` 和 `401008`。

## 範圍與限制 {/* scope-and-limits */}

這些是當前套件的限制，不構成交付計劃。

| 能力 | 現狀 |
| --- | --- |
| 透過 WebSocket 下單 | 未實作，下單走 HTTP |
| 真實密碼 / 二次驗證的交易鑑權 | 預設的首個令牌取得已隨 `exchangeTradeToken` 提供；2FA 與使用者輸入真實密碼的子流程未做 |
| 前景與背景回呼 | 不需要；引擎自行重連 |
| 明確銷毀 | 重新載入頁面 |
| 單頁面服務多個租戶 | 無法實現；簽名密鑰編譯在產物內 |
