WhaleCore 是面向宿主 App 的行情、交易與資產一體化 iOS SDK，同時支援 Swift 與 Objective-C，公開 API 均以 `@objc` 暴露。支援的市場覆蓋港股、美股與 A 股，包含期權、窩輪、牛熊證、界內證等衍生品行情。

## 系統要求與安裝 {/* requirements-and-installation */}

- iOS 13.0+
- Swift 5.9+、Xcode 15+
- Swift 與 Objective-C 均可調用

WhaleCore 以原始碼資料夾形式交付（內含 `WhaleCore.podspec`），不經私有 Pod 來源分發。將交付的 `WhaleCore` 資料夾放入宿主工程目錄後，在 `Podfile` 中用 `:path` 指向該資料夾：

```ruby
platform :ios, '13.0'

target 'YourApp' do
  # :path 指向 WhaleCore.podspec 所在目錄（相對 Podfile 的路徑），按實際存放位置調整
  pod 'WhaleCore', :path => '../WhaleCore'
end
```

執行 `pod install` 完成安裝。

## 初始化 {/* initialize */}

應用程式啟動時調用一次 `WhaleCoreService.initialize(config:)`。該方法會校驗啟動參數，**參數非法時拋錯且不做任何初始化**，故需要 `try`：

```swift
import WhaleCore

// deviceId 需要「持久化、長期複用」——具體產生演算法與儲存方式由宿主 App 自行決定，
// 以下寫法僅演示持久化思路。
let deviceIdKey = "com.yourapp.whalecore.deviceId"
let deviceId: String = UserDefaults.standard.string(forKey: deviceIdKey) ?? {
    let generated = UIDevice.current.identifierForVendor?.uuidString ?? UUID().uuidString
    UserDefaults.standard.set(generated, forKey: deviceIdKey)
    return generated
}()

let config = WhaleCoreConfig(
    appKey: "your_app_key",
    appSecret: "your_app_secret",
    appId: "your_app_id",
    token: userAccessToken,
    refreshToken: userRefreshToken,
    defaultAccountChannel: "lb_hk",
    deviceId: deviceId,
    logLevel: .info,        // 可選，預設 .info
    language: .zhHK         // 可選，預設簡體中文，可傳 .zhCN / .en
)
// SDK 弱持有該代理，宿主必須自行強引用，否則代理釋放後 token 回調靜默失效
config.tokenDelegate = self
do {
    try WhaleCoreService.initialize(config: config)
} catch {
    print("SDK 啟動失敗: \(error.localizedDescription)")
}
```

**Objective-C：**

```objc
WhaleCoreConfig *config = [[WhaleCoreConfig alloc]
    initWithAppKey:@"your_app_key"
    appSecret:@"your_app_secret"
    appId:@"your_app_id"
    token:userToken
    refreshToken:userRefreshToken
    defaultAccountChannel:@"lb_hk"
    deviceId:[MyDeviceIdStore persistedDeviceId]
    logLevel:WhaleCoreLogLevelInfo
    language:WhaleCoreLanguageZhHK];
config.tokenDelegate = self;

NSError *initError = nil;
if (![WhaleCoreService initializeWithConfig:config error:&initError]) {
    NSLog(@"SDK 啟動失敗: %@", initError.localizedDescription);
}
```

<Note>
  `appKey`、`appSecret`、`appId`、`defaultAccountChannel` 由 WhaleCore 提供；`token`、`refreshToken` 由 Broker 登入流程取得，token 過期時 WhaleCore 自動用 `refreshToken` 續期。`deviceId` 為裝置唯一識別碼，由宿主 App 自行產生並持久化（SDK 不提供產生邏輯），必須在同一部裝置上保持穩定，且長度不得少於 32 個字元，否則啟動時拋出 `WhaleCoreErrorCode.invalidParameter`。登入後 SDK 會用它向伺服器登記推送裝置，每次啟動都換值會被登記成不同裝置。請勿把憑證或完整 token 寫入日誌。
</Note>

## Token 與交易鑑權 {/* tokens-and-trade-authentication */}

WhaleCore 自動刷新 access token，並透過 `tokenDelegate` 通知宿主變更結果（是否持久化、如何持久化由宿主自行決定）：

```swift
class AppSession: WhaleCoreTokenDelegate {
    func didRefreshToken(_ token: String, refreshToken: String) {
        // 處理新的 token / refreshToken，如需下次啟動複用可自行持久化
    }

    // 主 token 徹底失效（401，自動刷新也失敗）時的異步兜底，可選實作；
    // 逾時前必須回調 completion，回填非空 token 則自動寫回並重試請求。
    func resolveExpiredToken(completion: @escaping (String?, String?) -> Void) {
        AuthCoordinator.silentLogin { token, refreshToken in
            completion(token, refreshToken) // 失敗時回填 (nil, nil) 即走刷新失敗流程
        }
    }

    func didFailToRefreshToken(_ error: Error) {
        // refresh token 已失效且宿主兜底也失敗（含逾時 / 未實作 resolveExpiredToken），引導使用者重新登入
        AuthCoordinator.logout()
    }
}

config.tokenDelegate = AppSession()
config.tokenResolverTimeout = 30   // resolveExpiredToken 逾時（秒），預設 30
```

<Note>
  三個回調均為可選實作。未實作 `resolveExpiredToken` 時，401 兜底直接判失敗並回調 `didFailToRefreshToken`（也未實作該回調則僅記日誌）。`didFailToRefreshToken` 的 `error` 只是觸發本次失效的原始請求錯誤，僅供日誌排查，收到該回調即代表登入狀態徹底失效。並行請求同時收到 401 時，SDK 只調用一次 `resolveExpiredToken`，結果由等候中的請求共用。
</Note>

**交易鑑權由 SDK 全自動處理**，宿主無感知：交易作用域的調用（下單、改撤單、交易透傳請求等）由 SDK 內部完成交易 token 的取得與失效復原，無需任何設定。「宿主自行管理交易密碼」模式目前未對外開放，為後續版本預留。

## 生命週期 {/* lifecycle */}

```swift
// AppDelegate / SceneDelegate
WhaleCoreService.resume()   // 進入前台
WhaleCoreService.pause()    // 進入後台
```

登出或銷毀 SDK（使用者登出、切換帳戶等場景）：

```swift
WhaleCoreService.logoutAndDestroy()
```

<Note>
  `logoutAndDestroy()` 會將 SDK 還原到「未初始化」狀態：清除本機 token（記憶體 + 磁碟）、斷開全部 WebSocket、釋放業務服務與底層句柄。銷毀後可在同一行程內再次調用 `initialize(config:)` 重新登入（如切換使用者）；重新登入後需像冷啟動一樣重新註冊各服務的 delegate 並重新訂閱。建議在主執行緒調用，且調用期間不要並行調用其他業務 API。`resume()` / `pause()` 此前分別名為 `onResume()` / `onPause()`，舊名仍可用但已標記棄用，建議盡快遷移。
</Note>

## 公開服務 {/* public-services */}

| 模組 | 入口 | 能力 |
| --- | --- | --- |
| 行情 | `WhaleCoreService.quoteService()` | 行情訂閱（鏈式選擇資料類型）、期權鏈 / 詳情訂閱、K 線與分時 / 逐筆歷史查詢、行情快照、行情等級與裝置佔用 |
| 訂單 | `WhaleCoreService.orderService()` | 下單、查單、撤單、改單、條件單、附加單、持倉止盈止損、下單前置校驗、訂單預覽、交易卡券選券、批量撤單與即時推送 |
| 資產 | `WhaleCoreService.portfolioService()` | 資產訂閱、現金明細與持倉行情開關、會員資產設定、盈虧分析 |
| 自選股 | `WhaleCoreService.watchlistService()` | 分組與股票的增刪改查、排序、置頂、失效標的清理與即時推送 |
| 透傳請求 | `WhaleCoreService.requestService()` | 任意業務接口透傳，自動附加公共參數與鑑權頭，鑑權失效自動復原重試 |
| 期權計算 | `WhaleCoreOptionCalculator`（靜態工具） | 本機 Black-Scholes 計算：Greeks、理論價、內在 / 時間價值、距到期天數、到期盈利概率 |

  除期權計算器外，以上服務在 SDK 未初始化或已調用 `logoutAndDestroy()` 時存取會拋出 `appNotReady`。下單前置校驗能力已併入 `orderService()`，歷史獨立入口 `WhaleCoreService.orderValidationService` 仍可用但已棄用。
</Note>

## 核心概念 {/* core-concepts */}

以下規則貫穿多個模組，先建立一次認知，後文不再重複解釋。

**標的編碼（counterId）** 格式統一為 `"{type}/{market}/{code}"`：股票如 `"ST/US/AAPL"`、`"ST/HK/00700"`；期權額外編碼行使價、到期日與方向，如 `"OP/US/AAPL240119C190000"`。行情、訂單、自選、盈虧分析等所有按標的定位的接口均使用這一套編碼。

**帳戶渠道** `WhaleCoreConfig.defaultAccountChannel` 在初始化時確定，訂單服務與資產訂閱預設落在該渠道。訂單相關方法普遍提供 `accountChannel` 覆蓋參數（不傳即走預設渠道）；資產訂閱則要求明確傳入 `WhaleCoreAccountInfo`，由宿主用自身的渠道與 `aaid` 建構：

```swift
let account = WhaleCoreAccountInfo(accountChannel: "lb_hk", aaid: "your_aaid")
```

**Delegate 多播模式** 訂單、資產、自選三個服務的推送採用同一套模式：`addDelegate(_:)` 註冊、`removeDelegate(_:)` 移除，SDK **弱引用**持有觀察者（調用方需自行強持有，否則代理釋放後回調靜默失效），支援多個頁面同時註冊接收同一份推送。訂單服務額外具備「首個 delegate 註冊即自動開啟推送、最後一個移除即自動停止」的生命週期綁定，無需手動 subscribe。行情服務的行情等級通知（`addQuoteLevelDelegate(_:)`，見 [行情等級與裝置佔用](#quote-level-and-eviction)）遵循同一套弱引用多播模式。

**回調執行緒** SDK 的全部回調（推送 delegate、訂閱閉包、token 回調、Objective-C `completionHandler`）統一在主執行緒派發，宿主可在回調內直接更新 UI，無需自行切換執行緒。

**Swift 與 Objective-C 的方法映射** 所有公開類型均帶 `@objc`，三類 Swift 方法在 Objective-C 端遵循固定映射規律：

| Swift | Objective-C |
| --- | --- |
| `throws -> T` | `- (nullable T)xxxAndReturnError:(NSError **)error` |
| `static func initialize(config:) throws` | `+ (BOOL)initializeWithConfig:error:` |
| `async throws -> T` | `- (void)xxx:(void (^)(T, NSError *))completionHandler` |

`completionHandler` 統一在主執行緒回調，可直接更新 UI；Swift 側 `await` 返回則回到調用方自身的執行內容。具體互調寫法見 [Objective-C 互通](#objective-c-interop)。

## 行情服務 {/* quotes-service */}

行情服務的類型為 `WhaleCoreQuotesService`，透過鏈式 Builder 選擇需要的資料類型，調用 `.start` 啟動訂閱。

### 行情訂閱 {/* quote-subscription */}

```swift
let svc = try WhaleCoreService.quoteService()

let subscription = try await svc
    .subscribe(counterIds: ["ST/US/AAPL", "ST/HK/00700"])
    .detail        // 詳情行情（OHLC、市值、PE/PB、52 週高低）
    .depth         // 買賣盤
    .trade         // 逐筆成交
    .preTrade      // 美股盤前
    .postTrade     // 美股盤後
    .start { updates in
        for update in updates {
            print("\(update.counterId): \(update.stock.lastPrice ?? 0)")
        }
    }

// 退訂
await subscription.cancel()
```

<Note>
  訂閱建立失敗（SDK 未就緒、首次拉取失敗）時 `.start` 拋出；建立成功後運行期不再產生錯誤，資料經回調持續下發。可選資料類型：`list`、`detail`、`depth`、`trade`、`broker`、`preTrade`、`postTrade`、`nightTrade`、`totalView`、`totalViewBrief`。
</Note>

### 查詢快照與歷史資料 {/* quote-history-queries */}

```swift
// 查詢快照（同步，從記憶體快取讀取）
if let stock = svc.getStock(counterId: "ST/US/AAPL") {
    print(stock.lastPrice ?? 0)
}

// 拉取歷史 K 線（Swift async 便捷重載）
let klines = try await svc.getKlines(counterId: "ST/US/AAPL", klineType: .perDay, count: 100)
klines.forEach { print("\($0.timestamp): \($0.close)") }
```

其餘查詢能力：`getTimeshares(counterId:fiveDays:...)` 拉取當日或五日分時資料（繪製分時圖請用本接口，不要用 1 分鐘 K 線近似）；`getTrades(counterId:count:...)` 翻頁拉取歷史逐筆成交；`observeQuoteEvents(counterIds:onUpdate:)` / `observeKlineUpdates(counterIds:onUpdate:)` 在不建立新訂閱的前提下旁聽其他調用方已建立的行情 / K 線事件；`getInterestRate()` 讀取 SDK 內建無風險利率，供期權計算器展示使用。

### 期權行情訂閱 {/* option-quote-subscription */}

期權行情分兩種訂閱形態，擴展資料（行使價、IV、方向、OI、盤口）均從 `optionData` 讀取：

```swift
// 期權鏈批量訂閱：一組合約整體訂閱，隨互動整組替換（切到期日 / 捲動可見區）
let chainSub = try svc.subscribeOptionChain(counterIds: visibleContracts) { updates in
    for u in updates {
        let opt = u.stock.optionData
    }
}
chainSub.updateCounterIds(newVisibleContracts)  // 整組替換（捲動 / 切到期日）
await chainSub.cancel()                          // 離開頁面退訂

// 期權詳情訂閱：單合約，subtypes 由宿主鏈式自選
let detailSub = try await svc.subscribeOptionDetail(counterId: "OP/US/AAPL240119C190000")
    .list.detail.trade
    .start { updates in
        let opt = updates.first?.stock.optionData
    }
await detailSub.cancel()
```

<Note>
  Greeks 不隨行情推送下發——宿主自訂正股取正股價，餵給 `WhaleCoreOptionCalculator` 本機計算，見 [期權計算器](#option-calculator)。
</Note>

### 行情等級與裝置佔用 {/* quote-level-and-eviction */}

同一帳戶在多台裝置使用進階行情時互相搶佔。SDK 在每次行情工作階段鑑權成功後刷新一份等級與佔用狀態快照（各子市場的行情等級、是否延遲、功能可用性，以及是否被其他裝置佔用及佔用文案），並自動回應伺服器的佔用 / 等級變更通知（自動重新鑑權取回最新狀態）。

```swift
let svc = try WhaleCoreService.quoteService()
svc.addQuoteLevelDelegate(self)   // 註冊時已有快照立即回調一次，之後每次鑑權成功回調（主執行緒）

// 同步查詢最近快照
if let info = svc.quoteLevelInfo, info.isEvicted(market: "US") {
    showBanner(info.evictedDescribe)   // 展示佔用提示（文案隨 SDK 語言）
}

// 「重啟行情」：把使用權搶回本裝置；恢復後的等級經委託回調刷新
try await svc.reclaimQuoteAccess()
```

提示條展示、「今日不再提示」等 UI 策略由宿主自行決定；被佔用狀態請以 `isEvicted(market:)` / `isEvicted(subMarket:)` 成對維度判斷，不要自行解析 `quoteLevel` 字串。渲染「N 檔盤口」請按 `depthType` 過濾 `depthLevel` 陣列取對應類型那條（普通盤口與深度盤口是兩類獨立權限）。

<Note>
  被佔用降級為延遲行情期間，對應市場的逐筆成交不可用（推送停發、歷史逐筆查詢返回空）；夜盤、盤前盤後等能力是否可用以快照中當前等級的 `hasOvernight` 等開關為準。「重啟行情」恢復後**標的本身的最新行情自動刷新、推送恢復，除此之外的資料不會自動補回**——被佔用期間的逐筆成交記錄缺失，需要完整序列時請在恢復後重新調用 `getTrades` 拉取。
</Note>

| `getStock(counterId:)` | 同步讀取行情快照（記憶體快取） |

| `getTimeshares(counterId:`<br />`fiveDays:`<br />`klineSession:)` | 上一方法的 Swift async 便捷重載（帶預設參數） |

| `getInterestRate()` | 讀取 SDK 內建無風險利率（年化小數），供期權計算器展示使用 |
| `quoteLevelInfo`（屬性） | 當前行情等級與佔用狀態快照（同步讀取；首次鑑權前為 `nil`） |
| `addQuoteLevelDelegate(_:)` | 註冊行情等級觀察者（每次鑑權成功後於主執行緒回調最新快照） |
| `removeQuoteLevelDelegate(_:)` | 移除行情等級觀察者 |
| `reclaimQuoteAccess()` | 把行情使用權搶回本裝置（「重啟行情」）；成功後自動重新鑑權 |
| `reclaimQuoteAccess(completion:)` | 上一方法的 Objective-C 便捷入口（completion 於主執行緒回調） |

## 期權計算器 {/* option-calculator */}

`WhaleCoreOptionCalculator` 是無狀態純計算工具（全靜態方法，不註冊進 `WhaleCoreService`、無網路），資料全部由調用方傳入，基於 Black-Scholes 歐式期權定價：行情場景下正股價來自宿主自訂的正股行情，IV / 行使價 / 距到期天數 / 分紅來自期權推送（`optionData`），每次推送重算；計算器場景（假設推演）把正股價 / 剩餘天數換成使用者假設值，套用同一公式。

```swift
let input = WhaleCoreOptionPricingInput(
    underlyingPrice: NSDecimalNumber(string: "190.00"),   // 正股現價（未減分紅）
    strikePrice: NSDecimalNumber(string: "185.00"),
    impliedVolatility: NSDecimalNumber(string: "0.25"),   // 年化 IV，小數（0.25 = 25%）
    daysToExpire: NSDecimalNumber(value: 30),             // 距到期天數，支援小數天（[0,1) 按 1 天計，負數非法）
    isCall: true,
    dividendToExpire: nil,                                // 到期前累計分紅，nil = 0
    interestRate: nil                                     // nil = 讀 SDK 內建無風險利率
)
if let g = WhaleCoreOptionCalculator.greeks(input) {
    print(g.delta, g.gamma, g.vega, g.theta, g.rho, g.theoreticalPrice)
    // 縮放口徑：vega 每 1% 波動率、theta 每自然日（通常為負）、rho 每 1% 利率
}

// 距到期整數自然日（greeks / profitProbability 的 daysToExpire 入參也支援小數天，
// 需要按小時折算的浮點天數時由宿主自行計算後傳入）
let days = WhaleCoreOptionCalculator.daysToExpire(
    expireDate: "20260729",                              // yyyyMMdd，同 optionData.expireDate
    timeZone: TimeZone(identifier: "America/New_York")!)  // 到期日所屬交易所時區
```

另有 `intrinsicValue(underlyingPrice:strikePrice:isCall:)`（內在價值：Call = max(0, 現價 − 行使價)，Put 相反）、`timeValue(optionPrice:intrinsicValue:)`（時間價值 = 權利金 − 內在價值）、`profitProbability(...)`（到期盈利概率，Black-Scholes 風險中性口徑）。

<Note>
  非法輸入統一回傳 `nil`（UI 按 "--" 展示）：IV ≤ 0、天數 < 0、減分紅後正股價 ≤ 0、行使價 / 盈虧平衡點 ≤ 0、利率為 0（含內建利率不可用）。`interestRate` 傳 `nil` 時讀 SDK 內建無風險利率（伺服器設定，登入後自動就緒）；`daysToExpire(expireDate:timeZone:)` 到期當天為 0、已過期為負，負數傳入計算 API 即回傳 `nil`。
</Note>

**方法一覽：**

| 方法 | 說明 |
| --- | --- |
| `greeks(_:)` | 計算 Greeks（delta / gamma / vega / theta / rho）與理論價 |
| `intrinsicValue(underlyingPrice:`<br />`strikePrice:`<br />`isCall:)` | 計算內在價值：Call = max(0, 現價 − 行使價)，Put 相反 |
| `timeValue(optionPrice:`<br />`intrinsicValue:)` | 計算時間價值 = 權利金 − 內在價值 |
| `daysToExpire(expireDate:`<br />`timeZone:)` | 計算距到期整數自然日數（「剩 N 天」類展示口徑） |
| `fractionalDaysToExpire(expireDate:`<br />`timeZone:`<br />`holidays:`<br />`dayOffset:)` | 計算距到期小數天：到期時刻取到期日 20:00、按小時折算；傳節假日表時為交易日口徑 |
| `profitProbability(underlyingPrice:`<br />`breakevenPoint:`<br />`impliedVolatility:`<br />`daysToExpire:`<br />`isCall:`<br />`dividendToExpire:`<br />`interestRate:)` | 計算到期盈利概率（Black-Scholes 風險中性口徑） |

## 訂單服務 {/* orders */}

訂單服務的類型為 `WhaleCoreOrderService`。

### 推送訂閱 {/* order-push-subscription */}

訂單推送透過 `addDelegate` / `removeDelegate` 自動管理（見 [Delegate 多播模式](#core-concepts)）：

```swift
class OrderHandler: NSObject, WhaleCoreOrderServiceDelegate {
    func onOrderChanged(order: WhaleCoreOrder) {
        print("訂單變更: \(order.orderId ?? "")")
    }
}

let handler = OrderHandler()
try WhaleCoreService.orderService().addDelegate(handler)
// handler 釋放後自動停止訂閱
```

### 建構並提交訂單 {/* submit-order */}

`WhaleCoreOrderSubmitRequest` **不可直接 `init`**，建構分兩步：先建公共參數 `WhaleCoreOrderCommon`，再按訂單類型選工廠方法。以最常見的限價單為例：

```swift
// 第一步：公共參數
let common = WhaleCoreOrderCommon(
    counterId: "ST/US/AAPL",
    action: .buy,
    quantity: .byCount(NSDecimalNumber(value: 100)),      // 或 .byAmount(_:count:) 按金額下單
    settlementCurrency: "USD",
    clientRequestId: myRequestId       // 冪等防重鍵；無自有鍵體系時傳 UUID().uuidString 並持有
)
common.validity = .day()               // 有效期，預設當日有效；GTD 用 .gtd(expireTime:)

// 第二步：按類型選工廠方法（此處為限價單）
let limitReq = WhaleCoreOrderSubmitRequest.limit(
    common: common,
    kind: .lo,                               // 或 .slo / .alo / .elo / .odd
    price: NSDecimalNumber(string: "180.00")
)

// 提交
let result = try await WhaleCoreService.orderService().submitOrder(limitReq)
print("提交成功: \(result.orderId ?? "")")
```

公共參數與可選屬性：

| 參數 | 類型 | 說明 |
| --- | --- | --- |
| `counterId` | `String` | 標的編碼 |
| `action` | `WhaleCoreOrderSide` | 買賣方向：`.buy` / `.sell` |
| `quantity` | `WhaleCoreOrderQuantity` | `.byCount(_:)` 按數量 / `.byAmount(_:count:)` 按金額，二者互斥 |
| `settlementCurrency` | `String` | 結算幣種，如 `"USD"`、`"HKD"` |
| `clientRequestId` | `String` | 冪等防重鍵，伺服器按此值對重複請求去重 |
| `validity`（可選） | `WhaleCoreOrderValidity` | 有效期，預設 `.day()`；GTD 用 `.gtd(expireTime:)` |
| `forceOnlyRth`（可選） | `WhaleCoreForceOnlyRTH` | 交易時段控制，預設 `.unknown`（不下發）；僅美股適用 |
| `remark`（可選） | `String?` | 使用者備註 |
| `cardIds`（可選） | `[String]` | 本單使用的卡券 ID，預設空陣列 = **本單不使用任何卡券**（SDK 不會自動補預設券）。僅自行建構請求時才需要填，走校驗漏斗時由 SDK 從 `intent.cards` 派生，見 [交易卡券](#trade-cards) |

按金額下單時，伺服器要求 `quantity` 恆為真實股數（`=0` 必拒），金額與換算股數需同時下發；僅限價、市價類型且買入方向支援，條件單（LIT/MIT/TSL）不支援按金額。建議走 [下單前置校驗](#order-validation) 漏斗，換算由 SDK 自動完成（金額 ÷ 價格向下取整，碎股 4 位小數、整手市場按手圓整）。

### 更多訂單類型與附加單 {/* order-types-and-attached-orders */}

除限價單外還提供：

- **市價類（MO/MOC/AO）**：`WhaleCoreOrderSubmitRequest.market(common:kind:)`，無需委託價。
- **觸價限價單（LIT）**：`limitIfTouched(common:price:triggerPrice:trend:marketPrice:)`，`trend` 按「觸發價 vs 目前市價」自動推導（`.up` / `.down`），不應讓使用者選擇。
- **觸價市價單（MIT）**：`marketIfTouched(common:triggerPrice:trend:marketPrice:)`，觸發後按市價成交，無委託價。
- **追蹤止損限價單（TSL）**：`trailingStopLimit(common:percent:limitOffset:limitDepthLevel:monitorPrice:)`，限價腿二選一（`limitOffset` 指定價差 / `limitDepthLevel` 掛單檔位，二者互斥；`limitDepthLevel` 正數=賣 N 檔（賣一 = 1）、負數=買 N 檔（買一 = -1），走檔位時 `limitOffset` 傳 `nil`），`monitorPrice` 必傳。

```swift
let mkt = NSDecimalNumber(string: "176.00")          // 目前市價
let trigger = NSDecimalNumber(string: "180.00")
let litReq = WhaleCoreOrderSubmitRequest.limitIfTouched(
    common: common,
    price: NSDecimalNumber(string: "178.00"),
    triggerPrice: trigger,
    trend: trigger.compare(mkt) == .orderedDescending ? .up : .down,
    marketPrice: mkt
)
```

<Note>
  獨立的追蹤止損市價單（TS）已下線，僅存量訂單回顯，不提供下單工廠；附加單場景的「觸發後下市價單」用 `.marketIfTouched()` 啟用。
</Note>

**掛載附加單（止盈 / 止損）**：任意訂單類型均可透過 `.attaching(_:)` 鏈式掛載附加單，主單成交後自動啟用。三層工廠組合：整體類型（`WhaleCoreAttachedParams.takeProfit` / `.stopLoss` / `.bracket`）、啟用方式（`WhaleCoreAttachedActivation.marketIfTouched()` / `.limitIfTouched(...)`）、有效期（`WhaleCoreOrderValidity`）。

```swift
// 止盈止損組合（bracket）—— 觸發後以限價成交
let bracket = WhaleCoreOrderSubmitRequest
    .limit(common: common, price: NSDecimalNumber(string: "180.00"))
    .attaching(.bracket(
        takeProfitPrice: NSDecimalNumber(string: "200.00"),  // 止盈觸發價
        stopLossPrice:   NSDecimalNumber(string: "170.00"),  // 止損觸發價
        validity: .gtc(),                        // 附加單撤單前有效
        activation: .limitIfTouched(             // 觸發後下限價單
            profitTakerSubmitPrice: NSDecimalNumber(string: "199.50"),
            stopLossSubmitPrice:    NSDecimalNumber(string: "170.50")
        )
    ))
```

<Note>
  `WhaleCoreOrderValidity` 與 `WhaleCoreAttachedActivation` 均透過工廠方法在 API 層封死了非法組合——GTD 必須攜帶到期時間、LIT 啟用必須攜帶對應委託價——無需業務層額外校驗。
</Note>

### 查單、撤單與改單 {/* order-query-cancel-replace */}

所有業務方法不再傳入帳戶，SDK 內部統一使用 `defaultAccountChannel` 對應的預設帳戶渠道：

```swift
let svc = try WhaleCoreService.orderService()

// 當日訂單（狀態篩選用 WhaleCoreTodayOrderStatus 的 Int 常數）
let todayFilter = WhaleCoreOrderFilter()
todayFilter.status = [WhaleCoreTodayOrderStatus.withdrawable]        // 可撤單
let todayOrders = try await svc.getTodayOrders(filter: todayFilter)

// 訂單詳情（主單）
let detail = try await svc.getOrderDetail(orderId: "12345").order

// 撤單
try await svc.cancelOrder(orderId: "12345")

// 普通改單（修改價格 / 數量 / 備註；quantity 必填——不修改數量時回傳原委託數量）
let replaceReq = WhaleCoreReplaceOrderRequest(orderId: detail.orderId ?? "",
                                              quantity: detail.quantity)
replaceReq.price = NSDecimalNumber(string: "152.00")
try await svc.replaceOrder(replaceReq)

// 批量撤單
try await svc.batchCancelOrders(counterId: "ST/US/AAPL")   // 按標的撤單（不限方向）
try await svc.batchCancelOrdersByIds(orderIds: ["1", "2", "3"])
```

改附加單使用獨立的 `WhaleCoreReplaceAttachedRequest`（僅支援改觸發價與 LIT 啟用的委託價），按操作意圖選擇 `.modifyProfitTaker` / `.modifyStopLoss` / `.modifyBracket` / `.removeAll` 工廠方法，子單 ID 從 `WhaleCoreOrder.attachedOrders` 按類型過濾取得；改主單時如需同步移除附加單，用 `WhaleCoreReplaceOrderRequest.removingAttachedOrders()`（原子操作）。條件單（LIT/MIT/TSL）改單走獨立的 `WhaleCoreReplaceOrderRequest.condition(...)` 工廠，`triggerStatus` 必傳，SDK 據此在未觸發（條件單改單端點）與已觸發（普通改單端點，僅價 / 量 / 備註生效）之間路由。期權改單同樣走獨立端點：普通期權改單用 `.option(orderId:quantity:price:)`，期權條件單改單用 `condition(..., isOption: true)`。

<Note>
  `replaceOrder` 恆走主單改單通道：透過 `attaching(_:)` 調整附加單時，主單價 / 量保持 `nil` 即可，SDK 自動以訂單快取中的原值補齊。只改附加觸發價 / 委託價也可用獨立的 `replaceAttachedOrder`，二者任選。
</Note>

### 下單前置校驗 {/* order-validation */}

黑盒校驗能力：宿主只傳訂單意圖，取數、快取、新鮮度由 SDK 內部管理。每條 issue 都意味著「按目前意圖提交必然失敗」，無警告級別；業務不通過不拋錯，一律以 `issues` 回傳（`throws` 僅基礎設施失敗）。

<Note>
  校驗能力已按域併入訂單服務，直接經 `WhaleCoreService.orderService()` 調用。歷史獨立入口 `WhaleCoreService.orderValidationService` 已棄用但仍可用，建議盡快遷移到新入口。
</Note>

主流程是單向漏斗（`WhaleCoreOrderIntent` 是唯一的建構入口）：

```swift
let svc = try WhaleCoreService.orderService()

// 進交易頁前：可交易性檢查
let entry = try await svc.checkTradability(counterId: "ST/US/AAPL")
guard entry.passed else { return handle(entry.issues) }

// 頁面渲染約束（每手股數 / 支援的訂單類型與時段 / 必填矩陣等），並預熱校驗快取
let constraints = try await svc.getOrderConstraints(counterId: "ST/US/AAPL")

// 輸入變化 → 輕量校驗驅動按鈕狀態（命中快取微秒級回傳）
let intent = WhaleCoreOrderIntent(counterId: "ST/US/AAPL", action: .buy, orderType: WhaleCoreOrderType.LO)
intent.price = NSDecimalNumber(string: "150.00")
intent.quantity = NSDecimalNumber(value: 100)
intent.validity = .day()
intent.forceOnlyRth = .rthOnly
let draft = try await svc.validateOrder(intent, scope: .draft)
submitButton.isEnabled = draft.passed

// 點擊下單 → 全量校驗；通過即拿到物化好的提交請求（校驗物件 == 提交物件）
let result = try await svc.validateOrder(intent, scope: .submission)
if let request = result.request {
    try await svc.submitOrder(request)
} else {
    for issue in result.issues {
        show(issue.reason)   // issue.reason 為多語言錯誤描述，可直接展示
    }
}
```

校驗規則按下單流程分成 10xx（進頁前）到 17xx（持倉止盈止損）共 7 段：

| 段 | 覆蓋 |
| --- | --- |
| 10xx 進頁前 | 空標的、帳戶未開戶 / 已暫停、指數類不可交易、伺服器可交易性判定 |
| 11xx 按鈕狀態 | 訂單類型支援性、渠道不支援、買賣受限、必填欄位、按金額下單的類型與方向限制、**現金卡僅買入**（1115，`issue.field` 為 `.cashCard`，見 [交易卡券](#trade-cards)）（收市 / 停牌可掛單，不攔截，狀態經約束快照透出） |
| 1201 協議 | 期權風險協議未同意 |
| 13xx 參數合理性 | 按金額下單換算股數為 0、美股碎股按金額低於渠道最低金額（`fractional_min_amount`，最低值經 `issue.referenceValue` 攜帶） |
| 14xx 時段與有效期 | 所選時段 / 有效期不受該類型支援；未指定也攔。空清單語義兩條規則不同：空 `support_sessions` = 無時段維度、放行（宿主應隱藏時段選擇、不指定時段提交）；空 `support_time_in_forces` 仍 = 明確全禁 |
| 15xx 資格與聲明 | 衍生品 ETF 認知、沽空 / 融券資格、W8BEN、美股夜盤 / 期權夜盤 / 碎股聲明、場外交易（OTC）權限、渦輪牛熊證披露、CAR / CKA 認證、虛擬資產 ETF 測評與披露 |
| 16xx 附加單 | 止盈止損觸發價必填；LIT 啟用時對應腿委託價必填（方向反了屬軟提醒，歸宿主處理，SDK 不攔截） |
| 17xx 持倉止盈止損 | 僅 `validateTPSLOrder` 產出，見 [持倉止盈止損](#position-tpsl) |

資格狀態與解決通道（issue 只報告「哪裡不通過」，怎麼解決按資格資料分流）：

```swift
for q in try await svc.getQualifications(counterId: "ST/US/AAPL") where !q.isSatisfied {
    if q.type == .listedDerivEtfAssessment {
        // 認知評估：SDK 內可完成，但入口是作答而非一鍵同意——須先於 acceptableViaAPI 分支判定。
        // 宿主渲染四選項問卷，作答須來自使用者本人（選 .none 記為不通過）
        try await svc.submitListedDerivAssessment(experience: .trained)
    } else if q.acceptableViaAPI {
        // 聲明類（期權協議 / 美股沽空 / 夜盤 / 期權夜盤 / 碎股 / 場外交易 OTC / 渦輪牛熊 /
        // CAR-CKA / 虛擬資產 ETF 測評與披露）：展示披露 → 使用者確認 → 一鍵同意
        try await svc.acceptAgreement(q.type)
    } else {
        // 測評 / 認證類（港股融券 / W8BEN 等）：跳轉 Web 流程，連結經 getOrderInfo(...) 按資格類型取用
        openWeb(urlFromOrderInfo(for: q.type))
    }
}
// 同意 / 作答成功後 SDK 自動失效快取，重走校驗即拿到最新狀態
```

<Note>
  `issue.reason` 與錯誤碼預設描述均為多語言（zh-Hans / zh-Hant / en），隨初始化設定或 `setLanguage(_:)` 切換。
</Note>

### 交易卡券 {/* trade-cards */}

免佣卡、現金卡、平台費卡的選券能力。**查券歸宿主、選券之後歸 SDK**：卡券清單一次 HTTP 請求即可取數、欄位直接上 UI，SDK 不建模券清單，宿主經[通用 HTTP 請求](#general-http-requests)自行查詢與渲染。把使用者選中的券填進 `WhaleCoreTradeCards` 掛到 `intent.cards` 之後，訂單預覽的折後費用重算、券面幣種匯率換算、下單報文的卡券欄位派生全部自動完成。

```swift
let cards = WhaleCoreTradeCards()
// 每類一個槽位，只需選中券的 4 個值；標題 / 有效期 / 說明文案留在宿主 UI，SDK 不需要
cards.commissionCard = WhaleCoreTradeCard(
    cardId: "card-1",
    availableAmount: NSDecimalNumber(string: "50"),    // 抵扣額度上限
    rebateRate: NSDecimalNumber(string: "0.3"),        // 返 30%；僅免佣卡槽位生效
    currency: WhaleCoreCurrency.hkd)                   // 券面幣種；與結算幣不同時自動換算

intent.cards = cards        // 掛到校驗用的 intent 上；預覽與下單報文同時生效，無需其他調用
```

三個槽位（`commissionCard` / `cashCard` / `platformFeeCard`）本身就是選券規則：同類別只能選一張、最多三張，都在**編碼期**就寫不出違規寫法。唯一需要執行期判定的是「現金卡僅買入」——賣出方向攜帶 `cashCard` 時 `validateOrder` 回傳 `.cashCardNotApplicableOnSell`（1115），`issue.field` 為 `.cashCard`，可據此把選券入口標紅。

**未選券 = 本單不使用任何卡券**：三個槽位全空（或不設 `intent.cards`）時報文 `card_ids` 為空陣列，伺服器**不核銷任何券**——不要理解成「伺服器會替你挑一張預設券」。`cardId` 為空字串的槽位同樣視作未選：不進報文、不觸發「現金卡僅買入」判定，`WhaleCoreTradeCards.isEmpty` 也把它算作未選。

伺服器為標的設定的預設券是**建議值**，隨約束快照一併下發（`WhaleCoreOrderConstraints` 的 `suggestedCommissionCard` / `suggestedCashCard` / `suggestedPlatformFeeCard`，或按類別取的 `suggestedCard(for:)`），無須再單獨調 `getOrderInfo`。但真實使用必須由宿主明確回填——**SDK 不會自動回填預設券**，用不用、用哪張始終是宿主的決定：

```swift
let constraints = try await svc.getOrderConstraints(counterId: "ST/US/AAPL")
let cards = WhaleCoreTradeCards()
// 槽位為 nil = 伺服器未給該標的配這類券（宿主據此停用該類選券入口）
if let suggested = constraints.suggestedCard(for: .commission) {
    cards.setCard(suggested.asTradeCard(), for: .commission)   // 額度缺失時轉出 nil，不預填
    // suggested.cardType 同時是卡券清單接口 rebate_type 入參的正確取值
}
intent.cards = cards
```

三個選券入口互動同構、只有類別不同，可用類別存取器讓它們共用同一段渲染程式碼，與直接讀寫屬性完全等價：

```swift
cards.setCard(card, for: .commission)     // .commission / .cash / .platformFee
let picked = cards.card(for: .cash)       // 未選為 nil
if cards.isEmpty { /* 三槽均未選 */ }
```

<Note>
  **無券槽位不透出卡型**：伺服器沒配券時，對應 `suggested*` 槽位整個為 `nil`——即使 wire 上 `comm_card_type` 仍下發 `"0"`（`"0"` 是合法卡型「普通返佣卡」），也不會給出「空 ID + 類型 0」的佔位物件，避免宿主誤拿 `"0"` 當 `rebate_type` 查券而錯誤取到返佣券清單。`WhaleCoreOrderInfo` 上的 `commCardId` / `commCardType` 等 wire 原樣欄位仍保留，但經校驗漏斗的宿主建議一律改讀約束快照。
</Note>

**券面幣種自動換算**：券面幣種與訂單結算幣種不同時（如港幣券用於美股單），SDK 按匯率換算後再參與折後計算；幣種缺失或無對應匯率時按原額度計算。`rebateRate`（折扣率）**僅免佣卡槽位生效**，現金卡與平台費卡按純額度抵扣，填了也不參與計算；`nil` 或 `0` 按 `1` 處理（額度內全額抵扣，即滿減語義）。

**自行建構請求時的卡券載體**：不走校驗漏斗、自行建構 `WhaleCoreOrderSubmitRequest` 提交時，卡券經 `WhaleCoreOrderCommon.cardIds`（與報文一一對應的字串陣列）傳入。**這條路徑 SDK 不做任何卡券校驗**——順序、重複、空字串、「現金卡僅買入」一概不管，以伺服器核銷結果為準。需要這些約束由 SDK 兜底，請改走 `intent.cards` + `validateOrder`：經漏斗時 `cardIds` 由 SDK 按「免佣 → 現金 → 平台費」固定序自動派生，宿主無須接觸它。

**改單不帶券**：卡券綁定關係在下單時確定並鎖死，改單鏈路不攜帶任何卡券參數。改單頁可照常展示原訂單的已用券資訊（讀 `WhaleCoreOrder` 的 `cardIds` 及對應的抵扣金額 / 狀態欄位），但選券入口應置灰不可點。

<Note>
  切換買賣方向時記得把 `cashCard` 置 `nil`。忘了清不會被靜默放過——第一次跑就會拿到 1115，而不是等到線上發現金額對不上。`WhaleCoreOrderIntent.action` 本就不可變，換方向要新建意圖，天然是重新組裝選券的時機。
</Note>

### 訂單預覽 {/* order-preview */}

下單前的「訂單預覽」計算能力：預估金額 / 費用（折後）、融資利率利息、跨幣種佔用、期權凍結、成交後持倉成本、帳戶變動預覽（現金 / 可用現金 / 維持 / 初始保證金）與風險提示。方向、折後封頂、保證金因子等數學計算全部在 SDK 內完成，宿主只做可見性開關、標籤文案、格式化三件事。

```swift
// 與校驗 / 下單共用同一 Intent —— 編輯中的草稿可隨時預覽（欄位未填齊時出部分結果）
let intent = WhaleCoreOrderIntent(counterId: "ST/US/AAPL", action: .buy, orderType: WhaleCoreOrderType.LO)
intent.price = NSDecimalNumber(string: "150.00")
intent.quantity = NSDecimalNumber(value: 100)

// SDK 不獲取行情：期權行使價 / 方向、市價單參考價由宿主經 Context 傳入
let context = WhaleCoreOrderPreviewContext()
context.marketReferencePrice = lastPrice        // 市價單（MO）預估依賴此項；限價 / 觸價單無需

let result = try await svc.previewOrder(intent, context: context)
print("預估金額: \(result.orderAmount ?? 0)  費用合計: \(result.fees.total)  總額: \(result.orderTotal ?? 0)")
```

參考價規則：限價類用 `intent.price`；觸價市價單（MIT）用 `intent.triggerPrice`；市價單用 `context.marketReferencePrice`，未提供則金額類結果為 `nil`。`result.riskHint` 給出風險提示種類（如 `.marginRaisedOnClose`、`.financingNeeded`），文案由宿主決定；`result.action` 僅供展示與埋點，各項數值已按方向算好，不應據此重新分支計算。

**卡券折後口徑**：佣金、平台費、現金卡三項的折後值隨 [`intent.cards`](#trade-cards) 自動重算，口徑與下單報文嚴格一致——只有會進 `card_ids` 的券才產生抵扣，未選券（或 `cardId` 為空字串）時三項額度均為 `nil`、不打折。預覽**不會**回落到下單資訊裡的帳戶預設券：那只是伺服器的建議值，沒進報文就不會被核銷，按它打折會讓預估費用低於實付。**預覽裡減掉的券，恆等於報文裡帶走的券。**

自行組 `WhaleCoreOrderPreviewFields` 調同步計算核心時，三項額度的幣種分別經費用欄位組 `fields.fees`（`WhaleCoreOrderPreviewFeeFields`）的 `commCurrency`（免佣卡）、`platformDeductionsCurrency`（平台費卡）、`deductionsCurrency`（現金卡）傳入；三者均可空，為 `nil` / 空字串或匯率表中無對應幣種對時按原額度參與計算（不猜匯率，也不把額度抹成 0）。這條路徑上填什麼算什麼——想按預設券預覽就自行填入預設券的額度與比例，SDK 不代填也不代扣。

<Note>
  另有同步純計算入口 `WhaleCoreOrderPreviewCalculator.compute(_:)`，供宿主自行取數（含未使用 SDK 行情的場景）後直接計算。費用各分項已按 2 位小數取整，且 `fees.total` 恆等於各展示分項之和；折後值經 `WhaleCoreDiscountedAmount` 攜帶原值（`original`，供「原 X」劃線展示）。
</Note>

### 持倉止盈止損（TPSL） {/* position-tpsl */}

為已持有的倉位一次掛出止盈、止損兩條條件單。與「掛載附加單」是兩回事——附加單依附於一筆新下的主單、主單成交後才啟用；TPSL 直接作用於已有持倉，不需要主單。買賣方向不由調用方指定，SDK 在校驗階段讀持倉推導後寫入請求。

```swift
let intent = WhaleCoreTPSLOrderIntent(counterId: "ST/US/AAPL")
intent.quantity = NSDecimalNumber(value: 100)
intent.wantsTakeProfit = true
intent.takeProfitTriggerPrice = NSDecimalNumber(string: "260")
intent.takeProfitOrderType = WhaleCoreOrderType.LIT      // 觸發後限價掛單，須填委託價
intent.takeProfitSubmitPrice = NSDecimalNumber(string: "259")
intent.wantsStopLoss = true
intent.stopLossTriggerPrice = NSDecimalNumber(string: "180")
intent.stopLossOrderType = WhaleCoreOrderType.MIT        // 觸發後市價掛單，無委託價

let result = try await svc.validateTPSLOrder(intent, scope: .submission)
if let request = result.request {
    let submitted = try await svc.submitTPSLOrder(request)
    print(submitted.ployId)          // 分組鍵，用於在訂單清單中配對兩腿
}
```

止盈、止損兩側參數各自獨立，未開啟的一側整組不提交，但兩側至少開啟一個。觸發後的訂單類型只能是 `WhaleCoreOrderType.LIT`（須填對應側委託價）或 `.MIT`（市價）。SDK 不代算預設觸發價（如「成本價 ±10%」）——用 `holding.averageCost` 自行推算。掛出的兩條訂單在訂單清單中 `ployId` 相同、`ployType` 分別為 `.takeProfit`（`"8"`）與 `.stopLoss`（`"9"`），只掛一條腿時 `ployId` 為空字串。

<Note>
  改單撤單不走本接口：TPSL 掛出的就是普通條件單，改單用 `replaceOrder` + `WhaleCoreReplaceOrderRequest.condition(...)`，撤單用 `cancelOrder`。校驗規則還包括觸發價方向顛倒（按持倉多空判定）；觸發價與現價的相對位置、數量是否超出可平數量這兩項校驗**有意不攔**（穿價視為合法意圖、可平數量為快照資料，均交伺服器裁決）。校驗命中「品種不支援」或「無持倉」時只回傳一條 issue，宿主按 `issues.first` 取根因即可。
</Note>

## 資產服務 {/* portfolio-service */}

資產服務的類型為 `WhaleCorePortfolioService`。

```swift
class PortfolioHandler: NSObject, WhaleCorePortfolioServiceDelegate {
    func onMessage(accountInfo: WhaleCoreAccountInfo, portfolioData: WhaleCorePortfolioData) {
        print("總資產: \(portfolioData.overview?.totalFortune ?? "")")
    }
    func onError(error: Error) {
        // 有帳戶歸屬的錯誤經 userInfo 攜帶渠道與 aaid：
        // (error as NSError).userInfo[WhaleCoreAccountChannelKey] / [WhaleCoreAccountAAIDKey]
        print("資產推送錯誤: \(error.localizedDescription)")
    }
}

let svc = try WhaleCoreService.portfolioService()
let handler = PortfolioHandler()
svc.addDelegate(handler)

// 訂閱資產推送（帳戶由宿主自行建構，整體替換全域訂閱範圍；傳空清單 = 取消全部訂閱）
let account = WhaleCoreAccountInfo(accountChannel: "lb_hk", aaid: "your_aaid")
svc.setSubscribedAccounts(accountChannels: [account], currency: "HKD")

// 現金明細 / 持倉行情開關（便捷屬性：設定即回傳、修改後立即生效）
svc.cashDetailEnable = true   // 推送將包含 cashBalance 欄位
svc.quotesEnabled    = true   // 持倉行情變化時即時重算資產

// 取得 SDK 目前正在使用的帳戶（含帳戶類型：現金 / 融資），無需宿主從清單選取
if let account = await svc.currentAccount() {
    print("帳戶類型: \(account.accountType == .margin ? "融資" : "現金")")
}
```

<Note>
  帳戶類型 `WhaleCoreAccountInfo.accountType` 僅經 `currentAccount()` 取得的帳戶攜帶；宿主自建或推送回填的實例為 `.unknown`。`onError(error:)` 下發的推送通道錯誤已結構化：`unauthorized`（3006，登入狀態失效）/ `tradeAuthFailed`（1006，該帳戶交易令牌失效）/ `accountLimited`（3008，該帳戶交易受限）。需要感知提交結果的可等待版本（`enableCashDetail(_:)` / `enableQuotes(_:)` / `refresh()` 等）見下方方法一覽表。

<Note>
  模型鏡像伺服器回應（欄位名僅 snake_case → lowerCamelCase，不重新命名不裁剪），金額 / 比率 / unix 秒時間戳為原始字串透出，數值化與升跌配色由宿主處理。統計區間用 `WhaleCorePLPeriod` 明確二選一（`.allTime` / `.range(start:end:)`）。幣種 / 市場傳字串常數（參考 `WhaleCoreCurrency` / `WhaleCoreMarket`）。全部方法 `async throws`，SDK 未初始化拋 `appNotReady`。
</Note>

**趨勢點的當期與累計收益率**：趨勢點同時給出「當期」與「累計」兩組收益率，隨粒度變義（日粒度 = 當日、月粒度 = 當月）——當期率為 `point.simpleEarningYield` / `point.timeEarningYield`，累計率為 `point.accumulateSimpleEarningYield` / `point.accumulateTimeEarningYield`。兩者可空性不同：累計率有兜底、不為 `nil`；當期率不做回退，伺服器未返回即為 `nil`（當月率 ≠ 當月末日的日率）。指數對比點同樣兩口徑並存：`indexPoint.cumulativeReturn`（累計）與 `currentReturn`（當期）；`currentReturn` 是相對上一個曲線點的升跌幅，首點相對區間起點前最後一個交易日收市（故與累計值同值），非交易日沿用上一交易日價故為 `"0"`。

**趨勢與日曆同一份統計資料**：`getProfitTrend` 與 `getPLCalendar` 的盈虧數值取自同一次查詢（同幣種、同區間時兩者共用一次請求），因此趨勢點與日曆日格的同名收益率欄位逐位相同，可按日期直接對齊。`getPLCalendar` 的 `markets` 入參**只決定休市標記覆蓋哪些市場，不參與盈虧統計**，不會讓收益率變成「按市場過濾後」的值。日曆頁「每標的收益明細表」即同區間的 `getProfitRanking` 資料（傳單日區間即當日明細），無需獨立接口——該榜單無分頁參數、兩榜一次全量返回，WhaleCore 不做任何條數截斷，Top N 截取完全由宿主決定。

**統計區間的邊界與時區**：`.range(start:end:)` 的起訖 unix 秒原樣轉發，WhaleCore 不做零點對齊、不做閉開歸一；同時按**裝置本地時區**把起訖折算成日期字串一併下發，伺服器按日期取**閉區間**。據此：

- 查「某一天」，把 `end` 設為該日當天內的任一時刻（如 `23:59:59`）；**傳次日 `00:00:00` 會把次日一併帶出來**。
- 跨時區注意：日期字串隨裝置時區變化，UTC+8 的手機與美東對同一時刻折算出的日期可能差一天。要按哪個時區切「一天」，就按該時區自行算出 unix 邊界再傳入——WhaleCore 不替宿主選擇時區。
- 日期對齊是安全的：日曆的 `dateTime` / `dateKey` 與趨勢點的 `dateKey` 都是伺服器原值，不經用戶端時區換算，可直接用作 join 鍵。

## 自選服務 {/* watchlist-service */}

自選服務的類型為 `WhaleCoreWatchlistService`。回調採用[多播模式](#core-concepts)，用 `addDelegate(_:)` 註冊，支援多個頁面同時訂閱：

```swift
final class WatchlistHandler: NSObject, WhaleCoreWatchlistServiceDelegate {
    func onWatchlistUpdated(groups: [WhaleCoreWatchlistGroup],
                            stocks: [WhaleCoreWatchlistStock],
                            ties: [String]) {
        // ties：已置頂標的的 counterId 清單（按置頂展示順序），與 groups / stocks 同一幀內嚴格一致
        print("分組數: \(groups.count), 股票數: \(stocks.count), 置頂數: \(ties.count)")
    }
    // 以下均為可選實作
    func onWatchlistFundsUpdated(funds: [WhaleCoreWatchlistFund]) {}
    func onWatchlistNotesUpdated(notes: [String: String]) {}
    func onWatchlistSortUpdated(groupId: Int64, sortMode: String,
                                sortGroups: [WhaleCoreWatchlistSortGroup]) {}
}

let svc = try WhaleCoreService.watchlistService()
let handler = WatchlistHandler()
svc.addDelegate(handler)

// 重新整理自選（sub 預設 false：僅拉清單；傳 true 同時訂閱行情）
try await svc.refresh(sub: true)

// 股票：增刪 / 跨分組移動（removeGroups）
try await svc.addStocks(counters: ["ST/US/AAPL"], groups: [1], removeGroups: [], sub: true)
try await svc.removeStocks(counters: ["ST/US/AAPL"], groups: [1], removeAll: false)
```

<Note>
  基金 / 備註 / 置頂資料不提供唯讀快照屬性，統一經回調取得並由宿主自行持有：基金走 `onWatchlistFundsUpdated`、備註走 `onWatchlistNotesUpdated`、置頂清單走 `onWatchlistUpdated` 的 `ties` 參數。排序結果除 `setGroup` 的一次性回傳值外還有持續通道——價格排序模式下行情變化觸發的自動重排經 `onWatchlistSortUpdated` 推送最新結果。置頂（`tie` / `untie` / `sortTied`）、排序模式切換（`setGroup`）、重新排序（`resort`）、失效標的（`invalidTickers` / `removeInvalidTickers`）等操作見下方方法一覽表。
</Note>

## 通用 HTTP 請求 {/* general-http-requests */}

需要調用尚未由 WhaleCore 類型化 Service 封裝的 [TradingAPI](/zh-hk/trading-api/overview) 時，可以使用 `WhaleCoreService.requestService()`。接口路徑、參數和回應結構以 TradingAPI 文檔為準；宿主提供這些請求資訊，WhaleCore 自動補充簽名、鑑權、trace 等公共參數與請求頭。登入狀態或 trade token 失效時，SDK 會復原鑑權並自動重試一次。

`WhaleCoreHTTPRequest` 提供以下屬性：

| 屬性 | 類型 | 行為 |
| --- | --- | --- |
| `method` | `WhaleCoreHTTPMethod` | `.get`、`.post`、`.put` 或 `.delete` |
| `path` | `String` | 以 `/` 開頭的接口路徑 |
| `query` | `[String: Any]?` | 僅 GET、DELETE 生效；POST、PUT 會忽略 |
| `body` | `[String: Any]?` | 僅 POST、PUT 生效；GET、DELETE 會忽略 |
| `requiresTradeToken` | `Bool` | 為 `true` 時發送前確保 trade token 有效；預設為 `false` |

回應透過 `bodyString` 提供原始 JSON，透過 `bodyData` 提供 UTF-8 資料，並透過 `headers` 提供回應頭。Swift 可直接將回應解碼為 `Decodable` 模型。

```swift
struct MemberInfo: Decodable {
    let id: String
    let name: String
}

let request = WhaleCoreHTTPRequest(method: .get, path: "/v2/member/info")
request.query = ["include_accounts": true]

let response = try await WhaleCoreService.requestService().send(request)
let member: MemberInfo = try response.decode()
print(member.name)
```

調用需要交易鑑權的接口時，設定 `requiresTradeToken = true`，SDK 自動完成交易鑑權：

```swift
let tradeRequest = WhaleCoreHTTPRequest(method: .get, path: "/v5/orders/today")
tradeRequest.requiresTradeToken = true
let tradeResponse = try await WhaleCoreService.requestService().send(tradeRequest)
```

伺服器有回應的錯誤（`serverError` / `businessError` / `unauthorized`）`userInfo` 額外攜帶 `WhaleCoreHTTPStatusCodeKey`（HTTP 狀態碼）、`WhaleCoreBusinessCodeKey`（伺服器業務 code）、`WhaleCoreResponseBodyKey`（原始錯誤回應體）與 `WhaleCoreTraceIdKey`（鏈路追蹤 trace id）。

<Note>
  首個版本不支援自訂請求頭。請勿透過 `query` 或 `body` 傳入簽名或鑑權 token；WhaleCore 會透過受管會話自動添加。服務無狀態，`logoutAndDestroy()` 後請求拋 `appNotReady`。
</Note>

## 錯誤處理 {/* error-handling */}

所有錯誤以 `NSError` 形式拋出，統一域為 `WhaleCoreErrorDomain`，錯誤碼在 `WhaleCoreErrorCode` 中定義：

```swift
do {
    try await WhaleCoreService.orderService().submitOrder(request)
} catch let error as NSError where error.domain == WhaleCoreErrorDomain {
    switch WhaleCoreErrorCode(rawValue: error.code) {
    case .orderSubmitFailed:    // 2002
        showAlert("下單失敗：\(error.localizedDescription)")
    case .tradeAuthFailed:      // 1006
        promptReauth()
    default:
        log(error)
    }
}
```

| 段 | 範圍 | 模組 |
| --- | --- | --- |
| 通用 / 資產 | 1001–1008 | SDK 初始化、會員設定、交易鑑權、行情服務、內部匯率換算（1008 匯率不可用，宿主通常不會直接收到） |
| 訂單 | 2001–2006 | 下單 / 撤單 / 改單 / 查詢 / 前置校驗 |
| 通用請求 | 3001–3008 | 請求 / 推送失敗細分：未知失敗（3001）/ 網路不可用（3002）/ 逾時（3003）/ 伺服器 5xx（3004）/ 業務錯誤（3005）/ 會話失效（3006，覆蓋全部登入狀態失效業務碼）/ 參數錯誤（3007，如期權預覽未傳 `optionDirection`、啟動參數非法如 `deviceId` 過短）/ 帳戶交易受限（3008，資產推送錯誤通道下發，`userInfo[WhaleCoreAccountChannelKey]` 攜帶涉及帳戶） |

完整錯誤碼表請參考 `WhaleCoreErrorCode` 的懸停文檔。

## Objective-C 互通 {/* objective-c-interop */}

所有公開類型均帶 `@objc`，ObjC 端可直接使用。常見模式：

```objc
#import <WhaleCore/WhaleCore-Swift.h>

// 初始化（initializeWithConfig: 是 throws 方法，ObjC 側以 error: 出參暴露）
WhaleCoreConfig *config = [[WhaleCoreConfig alloc]
    initWithAppKey:appKey appSecret:appSecret appId:appId
    token:token refreshToken:refreshToken
    defaultAccountChannel:@"lb_hk"
    deviceId:[MyDeviceIdStore persistedDeviceId]
    logLevel:WhaleCoreLogLevelInfo
    language:WhaleCoreLanguageZhCN];

NSError *initError = nil;
if (![WhaleCoreService initializeWithConfig:config error:&initError]) {
    NSLog(@"SDK 啟動失敗: %@", initError.localizedDescription);
    return;
}

// 服務存取（throws 方法在 ObjC 側以 AndReturnError: 形式暴露）
NSError *svcError = nil;
WhaleCoreOrderService *orderSvc = [WhaleCoreService orderServiceAndReturnError:&svcError];
if (!orderSvc) { NSLog(@"%@", svcError); return; }
[orderSvc addDelegate:self];

// async 方法以 completionHandler 形式暴露
[orderSvc submitOrder:request
    completionHandler:^(WhaleCoreOrderSubmitResult *result, NSError *error) {
        if (error) { NSLog(@"%@", error); return; }
        NSLog(@"成功: %@", result.orderId);
    }];
```

<Note>
  Swift `async throws` 方法在 ObjC 端自動轉為 `completionHandler` 形式，`completionHandler` 統一在主執行緒回調，可直接更新 UI。
</Note>
