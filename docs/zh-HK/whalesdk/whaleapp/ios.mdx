## 系統要求

- **iOS 版本**: iOS 13.0+

- **Xcode 版本**: Xcode 12.0+

- **Swift 版本**: Swift 5.0+

- **架構支援**: 真機 (arm64)、模擬器 (x86_64 \&\& arm64)

- **開發語言**：Objective-C、Swift

- **其他**：不支援橫屏展示。

## 整合方式

*LBWhaleAppSDK* 提供兩種整合方式供 iOS 開發者選擇：

- 透過 CocoaPods 整合

- 手動整合

### CocoaPods 整合（推薦）

下載 `LBWhaleAppSDK-XXX.zip` 後解壓將 SDK 目錄複製到您專案根目錄下（目錄可以隨意，需要注意修改 `pod :path` ），在 `Podfile` 中新增：

```ruby
source 'https://github.com/volcengine/volcengine-specs.git'
source 'https://github.com/aliyun/aliyun-specs.git'

pod 'LBWhaleAppSDK', :path => './LBWhaleAppSDK'
```

然後執行：

```bash
pod install
```

### 手動整合

1. 下載 `LBWhaleAppSDK-XXX.zip` 後解壓

2. 將解壓後的 `LBWhaleAppSDK.xcframework` 拖入您的 Xcode 專案

3. 在 **General** → **Frameworks, Libraries, and Embedded Content** 中設定為 **Embed \& Sign**

4. 在 **Build Phases → Link Binary With Libraries** 中新增系統庫：

## 初始化 SDK

### 匯入標頭檔案

在程式碼中匯入標頭檔案

> `#import <LBWhaleAppSDK/LBWhaleApp.h>`
>
> *如果是 **`Swift`** 工程，請在對應**`bridging-header.h`**中匯入*
>
>

### 初始化 LBWhaleAppSDK

在開啟 SDK 頁面時，先初始化 SDK

```objective-c
// 建立多語言應用名稱
LBWhaleAppConfigMultilingual *appName = [[LBWhaleAppConfigMultilingual alloc] initWithEn:@"My Trading App"
    zhCN:@"我的交易應用"
    zhHK:@"我的交易應用"];
// 建立配置物件
LBWhaleAppConfig *config = [[LBWhaleAppConfig alloc] initAppKey:@"LB_app_key"
    appSecret:@"LB_app_secret"
    appId:@"LB_app_id"
    appName:appName
    defaultAccountChannel:@"your_account_channel"
    webDomainPrefix:@"your_domain_prefix"
    token:@"user_access_token"
    refreshToken:@"user_refresh_token"
    delegate:self
    extraCustomConfig:nil];
// 設定主題和語言（可選）
config.theme = LBWhaleAppConfigThemeAuto;
config.language = LBWhaleAppConfigLanguageEn;
// 啟動 SDK
[LBWhaleApp startWithConfig:config];
```

### 實現代理方法

`LBWhaleAppDelegate` 中所有方法均為 `@optional`，可根據業務需要選擇實現。以下按 SDK 生命週期順序逐一說明。

#### 錯誤碼速查表

SDK 回調中 `NSError` 的 `domain` 統一為 `@"LBWhaleApp"`，常見錯誤碼如下：

|error.code|含義|觸發場景|建議處理|
|---|---|---|---|
|400|配置引數錯誤|`startWithConfig:` 時缺少必填引數（appKey / appSecret / appId / appName.en / defaultAccountChannel / webDomainPrefix / token / refreshToken）或重複初始化|檢查 `LBWhaleAppConfig` 各欄位是否完整，修正後重新啟動|
|401|鑑權失效|使用者被異地登入踢出、token 重新整理失敗、SDK 未啟動時呼叫介面|呼叫 `[LBWhaleApp logoutAndDestroy]` 銷燬 SDK，引導使用者重新登入|
|403xxx|API Key 非法|服務端校驗 appKey 不合法|收到 403 開頭的錯誤，如：403201 或 403203 等確認 appKey 是否正確、聯絡服務端排查|

```objective-c
#pragma mark - LBWhaleAppDelegate

/// 1. SDK 啟動成功
///
/// 觸發時機：呼叫 [LBWhaleApp startWithConfig:] 後，SDK 內部初始化流程全部完成時觸發，僅觸發一次。
/// 建議處理：
///   - 記錄啟動成功日誌，用於排查問題
///   - 執行依賴 SDK 就緒的業務邏輯（如：進入行情頁、展示交易入口等）
- (void)lbWhaleAppDidFinishLaunching {
    NSLog(@"SDK 啟動成功");
    // 示例：SDK 就緒後展示交易入口
    [self showTradeEntryIfNeeded];
}

/// 2. SDK 啟動失敗
///
/// 觸發時機：呼叫 [LBWhaleApp startWithConfig:] 後，SDK 初始化過程中遇到不可恢復的錯誤時觸發。
///          兩類觸發來源：
///          a) 本地校驗失敗 —— config 必填引數缺失或重複初始化（error.code == 400）
///          b) 網路請求失敗 —— 啟動階段的 token 重新整理或介面請求返回鑑權錯誤（error.code == 401 / 403）
///             此情況下 SDK 會在回調後自動執行 logoutAndDestroy，Broker App 無需再手動銷燬
/// 引數說明：
///   - error.domain              : 固定為 @"LBWhaleApp"
///   - error.code                : 錯誤碼，參見上方「錯誤碼速查表」
///   - error.localizedDescription : 人類可讀的錯誤描述，如 "缺少 appKey 引數，請補充。"
/// 建議處理：
///   - code == 400 : 屬於接入問題，檢查 LBWhaleAppConfig 各必填欄位，修正後重新啟動
///   - code == 401 / 403 : 屬於鑑權問題，SDK 已自動銷燬，Broker App 只需引導使用者重新登入
///   - 所有情況均建議記錄日誌並上報監控
- (void)lbWhaleAppStartFailedWithError:(NSError *)error {
    NSLog(@"SDK 啟動失敗，code: %ld, msg: %@", (long)error.code, error.localizedDescription);
    [MyErrorTracker trackError:error];

    if (error.code == 400) {
        // 配置錯誤：提示開發者檢查引數
        NSLog(@"請檢查 LBWhaleAppConfig 配置項");
    } else {
        // 鑑權類錯誤：SDK 已自動銷燬，引導使用者重新登入
        [self redirectToLoginPage];
    }
}

/// 3. Token 自動重新整理通知
///
/// 觸發時機：SDK 內部檢測到 token 即將過期或已過期時，會自動執行 token 重新整理流程。
///          重新整理成功後透過此回調通知 Broker App；token 的有效性和後續續期仍由 WhaleAppSDK 管理。
/// 引數說明：
///   - token : 重新整理後的新 token 字串（非空），僅用於專案確有需要時同步觀察狀態。
/// 建議處理：
///   - Broker App 不需要呼叫 check token 或自行實現 refresh token 續期
///   - 不要與 WhaleAppSDK 同時維護另一套 token 重新整理狀態
- (void)lbWhaleAppTokenDidChange:(NSString *)token {
    NSLog(@"token 已重新整理");
    // WhaleAppSDK 已在內部完成續期，Broker App 通常無需處理新 token
}

/// 4. SDK 執行時錯誤
///
/// 觸發時機：SDK 啟動完成（狀態為 LBWhaleAppStatusStarted）後，執行過程中遇到異常時觸發。
///          啟動階段的錯誤不走此回調，而是走 lbWhaleAppStartFailedWithError:。
///          典型觸發源：
///          a) 網路請求返回鑑權錯誤，SDK 統一映射為 error.code == 401
///          b) token 自動重新整理失敗且服務端返回上述鑑權錯誤碼
/// 引數說明：
///   - error.domain              : 固定為 @"LBWhaleApp"
///   - error.code                : 錯誤碼。目前執行時回調的錯誤碼均為 401（鑑權失效）
///   - error.localizedDescription : 服務端返回的錯誤描述
/// 建議處理：
///   - code == 401 : 使用者已被異地登入踢出，必須呼叫 [LBWhaleApp logoutAndDestroy] 銷燬 SDK，
///                   並引導使用者重新登入
- (void)lbWhaleAppDidRunInError:(NSError *)error {
    if (error.code == 401) {
        // 鑑權失效：銷燬 SDK 並跳轉登入頁
        [LBWhaleApp logoutAndDestroy];
        [self redirectToLoginPage];
    }
}

/// 5. SDK 請求 Broker App 開啟 URL
///
/// 觸發時機：當 SDK 內部需要開啟一個自身無法處理的 URL 時觸發。包含兩種場景：
///          a) Broker App 透過 SDK 介面打開了一個 SDK 內頁面，但該頁面中包含 SDK 無法識別的跳轉連結
///          b) SDK 內部展示了服務端下發的運營內容（如 banner、公告），使用者點擊後的目標 URL 不在 SDK 路由表中
/// 引數說明：
///   - openUrl : 需要開啟的完整 URL 字串。可能是 HTTP 連結、深度連結（deeplink）或自定義 scheme
/// 建議處理：
///   - 使用 Broker App 自己的路由系統開啟該 URL
///   - 如果是 HTTP 連結，可選擇使用內建瀏覽器或跳轉外部瀏覽器
///   - 如果是無法識別的 URL，建議記錄日誌便於排查
/// 注意：若實現了 lbWhaleAppSDKCanOpenURL:，此方法僅在其返回 YES 之後才會被呼叫
- (void)lbWhaleAppSDKDidRequestOpenURL:(NSString *)openUrl {
    NSLog(@"SDK 請求開啟 URL: %@", openUrl);
    // 示例：交由 Broker App 路由系統處理
    [MyAppRouter openURL:openUrl];
}

/// 6. SDK 詢問 Broker App 是否能開啟某個 URL
///
/// 觸發時機：當 SDK 遇到自身無法識別的 URL 時，先透過此方法詢問 Broker App 是否有能力處理。
///          此方法的呼叫早於 lbWhaleAppSDKDidRequestOpenURL:，用於預判斷。
/// 引數說明：
///   - url : 待檢查的 URL 字串
/// 返回值：
///   - YES : 表示 Broker App 可以處理該 URL，SDK 後續會呼叫 lbWhaleAppSDKDidRequestOpenURL: 請求開啟
///   - NO  : 表示 Broker App 也無法處理，SDK 將自行決定後續行為（如忽略或提示使用者）
/// 注意：
///   - 若未實現此方法，SDK 預設視為 Broker App 不支援開啟
///   - 此方法可能在短時間內被多次呼叫，實現時應避免耗時操作
- (BOOL)lbWhaleAppSDKCanOpenURL:(NSString *)url {
    // 示例：檢查 Broker App 路由表是否註冊了該 URL
    return [MyAppRouter canOpenURL:url];
}

/// 7. SDK 即將銷燬
///
/// 觸發時機：呼叫 [LBWhaleApp logoutAndDestroy] 或 SDK 內部發生 401 錯誤後，
///          SDK 開始執行銷燬流程時觸發（此時 SDK 資源尚未完全釋放）。
/// 注意：
///   - 在 SDK 銷燬前完成需要的資料儲存或狀態儲存工作，SDK 銷燬後，頁面會直接關閉，例項也會立即釋放
- (void)lbWhaleAppWillDestroy {
    NSLog(@"SDK 即將銷燬");
    // 儲存資料並重置狀態
    [self storeAndReset];
}

/// 8. SDK 自動續期失敗兜底
///
/// 正常情況下 SDK 自動完成 token 校驗與續期。僅當 token 與 refresh_token 均無法續期時觸發。
/// 預設應返回 nil 結束重試，隨後在 lbWhaleAppDidRunInError: 中銷燬 SDK 並讓 Broker App 返回登出狀態。
/// 只有專案另有約定且 Broker 能取得一組全新的 Customer 憑證時，才返回新憑證。
- (void)lbWhaleAppRefreshTokenExpiredWithResolver:(void(^)(NSString *token, NSString *refreshToken))resolveCompleted {
    resolveCompleted(nil, nil);
}

/// 9. SDK 分析事件（可選）
/// 僅在專案需要承接 WhaleAppSDK 分析事件時實現；不要在事件屬性中補充 token 等敏感資訊。
- (void)lbWhaleAppAnalyticsEventWithName:(NSString *)name properties:(NSDictionary *)properties {
    [MyAnalytics track:name properties:properties];
}
```

<Note>
`lbWhaleAppRefreshTokenExpiredWithResolver:` 是極低機率異常的兜底擴充套件點，不是 Broker App 的常規 token 重新整理入口。等待時間預設 30 秒，可透過 `LBAPPSDKConfigKeyRefreshTokenResolverTimeout` 調整。
</Note>

### 監聽 SDK 頁面進出（可選）

將 `LBWhaleAppUIDelegate` 設定到 `config.sdkUIDelegate`，可以監聽第一個 SDK 頁面開啟和最後一個 SDK 頁面關閉。回調按頁面是否存在計算，不等同於 App 進入前臺或後臺。

```objective-c
config.sdkUIDelegate = self;

- (void)lbWhaleAppEnterSdkPage {
    // SDK 頁面數量從 0 變為 1
}

- (void)lbWhaleAppExitSdkPage {
    // SDK 頁面數量從 1 變為 0
}
```

### 頁面路由使用

使用路由介面開啟對應的頁面

```objective-c
// 簡單頁面跳轉
[LBWhaleApp pushURL:@"lb://page/main"]; // 主頁
[LBWhaleApp presentURL:@"lb://page/discovery/search-stocks"]; // 搜尋

// 帶引數的頁面跳轉
NSDictionary *params = @{
    @"id": @"ST/US/AAPL"
};

[LBWhaleApp pushURL:@"lb://page/stock/detail"
         parameters:params
          completed:^(BOOL isSuccessed, NSError * _Nullable error) {
    if (isSuccessed) {
        NSLog(@"頁面跳轉成功");
    } else {
        NSLog(@"頁面跳轉失敗: %@", error.localizedDescription);
    }
}];

[LBWhaleApp presentURL:@"lb://page/account/settings" parameters:nil completed:^(BOOL isSuccessed, NSError * _Nullable error) {
    if (!isSuccessed) {
        NSLog(@"頁面跳轉失敗: %@", error.localizedDescription);
    }
}];
```

### SDK 內橫屏頁面支援

獲取 SDK 當前頁面所需要支援的螢幕方向

```objective-c
// SDK 需要支援的 UIInterfaceOrientationMask，如果返回 NSNumber ：0，表示當前頁面非 SDK 頁面，由 Broker App 決定支援的方向
**+ (NSUInteger)requiredAppInterfaceOrientationMask*
```

為了使 SDK 內頁面可以正常顯示橫屏狀態，Broker App 需要在 AppDelegate 中實現以下代理方法

```objective-c
- (UIInterfaceOrientationMask)application:(UIApplication *)application supportedInterfaceOrientationsForWindow:(UIWindow *)window {
    NSUInteger mask = [LBWhaleApp requiredAppInterfaceOrientationMask];
    if (mask > 0) {
        return mask;
    }
    return UIInterfaceOrientationMaskPortrait;
}
```

## 訊息推送

SDK 支援兩種推送接入方式，請根據您的推送基礎設施情況選擇其一：

兩種方式互不依賴，按照實際場景接入對應小節即可。

### 方式一：走 SDK 內建渠道

Whale 透過 SDK 內建的推送通道直接下發訊息給 Broker App。Broker App 只需啟動推送服務並上報 `deviceToken`，後續通知展示與點擊路由由 SDK 負責（點擊跳轉依賴 SDK 主體已啟動，可參考各程式碼示例中的 `NotificationErrorNotStarted` 處理分支）。

#### 初始化推送服務

推送服務的啟動獨立於 SDK 主體啟動，建議在 App 啟動時即執行。

```objective-c
// 啟動推送服務（推送服務的啟動不依賴於 SDK，可獨立啟動，建議在應用啟動時就執行）
- (void)setupAPNs {
    // 啟動推送通知
    [LBWhaleApp.pushService startWithKey:@"push key" andSecret:@"push secret" andCompleted:^(NSError * _Nullable error) {
        if (error) {
            NSLog(@"push 服務啟動異常：%@", error.localizedDescription);
        }
    }];
//    執行其他邏輯如開啟通知許可權等...
//    UNUserNotificationCenter *center = [UNUserNotificationCenter currentNotificationCenter];
//    center.delegate = self;
//    [center requestAuthorizationWithOptions:(UNAuthorizationOptionAlert | UNAuthorizationOptionSound | UNAuthorizationOptionBadge)
//                          completionHandler:^(BOOL granted, NSError * _Nullable error) {
//        dispatch_async(dispatch_get_main_queue(), ^{
//            if (granted) {
//                [[UIApplication sharedApplication] registerForRemoteNotifications];
//            }
//            NSLog(@"推送許可權狀態: %@", granted ? @"已授權" : @"被拒絕");
//        });
//    }];
}
```

#### 上報 deviceToken

APNs 回調 `deviceToken` 後交給 SDK 完成使用者綁定。如果此時 SDK 還未啟動，SDK 僅記錄 `deviceToken`，待 SDK 啟動後再在後臺完成與使用者的關係綁定。`disableMultiDevices` 傳 `YES` 可禁止多裝置同時綁定（僅最新登入裝置收到推送）。

```objective-c
- (void)application:(UIApplication *)application didRegisterForRemoteNotificationsWithDeviceToken:(NSData *)deviceToken {
    [LBWhaleApp.pushService updateDeviceToken:deviceToken disableMultiDevices:YES callback:^(NSError * _Nullable error) {
        if (error) {
            NSLog(@"update DeviceToken 失敗：%@", error.localizedDescription);
        }
    }];
}
```

#### 處理冷啟動通知

App 未啟動時使用者點擊推送會觸發冷啟動，在 `didFinishLaunchingWithOptions:` 中將 `launchOptions` 透傳給 SDK：

```objective-c
- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    // 建議在啟動後優先執行推送服務初始化動作
    [self setupAPNs];
    NSError *error = [LBWhaleApp.pushService handleLaunchOptions:launchOptions];
    if (error.code == NotificationErrorNotStarted) {
        // SDK 未啟動
        // 啟動 SDK，啟動後再讓 SDK 處理該通知。可以放一些中間頁或者 loading 動畫等待 SDK 啟動。
    } else if (error.code == NotificationErrorNonSDK) {
        // 非 SDK 通知，Broker App 自行處理
    }
    return YES;
}
```

#### 處理前臺與點擊通知

App 已啟動時，iOS 10 及以上版本還需將 `UNUserNotificationCenterDelegate` 的兩個代理方法透傳給 SDK：

```objective-c
// APP 處於前臺時的代理方法
- (void)userNotificationCenter:(UNUserNotificationCenter *)center willPresentNotification:(UNNotification *)notification withCompletionHandler:(void (^)(UNNotificationPresentationOptions))completionHandler {
    // 先給到 SDK 處理通知推送，如果 SDK 無法處理則會返回 error
    NSError *error = [LBWhaleApp.pushService handleSystemDelegateUserNotificationCenter:center willPresentNotification:notification];
    if (!error) {
        // SDK 已處理，建議 Broker App 不再顯示系統通知
        completionHandler(UNNotificationPresentationOptionNone);
        return;
    }
    if (error.code == NotificationErrorNotStarted) {
        // SDK 未啟動
        // 考慮啟動 SDK，啟動後再讓 SDK 處理該通知
    } else if (error.code == NotificationErrorNonSDK) {
        // 非 SDK 通知，Broker App 自行處理
    }
}

// APP 處於後臺時的代理方法
- (void)userNotificationCenter:(UNUserNotificationCenter *)center didReceiveNotificationResponse:(UNNotificationResponse *)response withCompletionHandler:(void (^)(void))completionHandler {
    NSError *error = [LBWhaleApp.pushService handleSystemDelegateUserNotificationCenter:center didReceiveNotificationResponse:response];
    if (!error) {
        // SDK 已處理
        completionHandler();
        return;
    }
    if (error.code == NotificationErrorNotStarted) {
        // SDK 未啟動
        // 考慮啟動 SDK，啟動後再讓 SDK 處理該通知
    } else if (error.code == NotificationErrorNonSDK) {
        // 非 SDK 通知，Broker App 自行處理
    }
}
```

### 方式二：走 Broker 自己的渠道

Broker App 已經有自有推送通道（如 FCM、自有後端等），訊息送達由 Broker App 自己負責。在這種場景下 SDK 不接管 APNs 註冊，也無需呼叫 `startWithKey:andSecret:andCompleted:` 或 `updateDeviceToken:disableMultiDevices:callback:`；Broker App 在自有通道收到訊息後，判斷出屬於 Whale 的訊息並把訊息字典透傳給 SDK，由 SDK 完成前臺 tip 展示與路由跳轉即可。

適用於以下情況：

- 推送資料來源不是標準的 APNs；

- Broker App 需要在 SDK 處理前對推送資料進行預處理、格式轉換或校驗；

- 已有穩定的自有推送體系，不希望額外引入 SDK 內建推送通道。

#### 識別是否為 Whale 訊息

Broker App 從自有通道收到訊息後，先用 `checkIsLBNotificationWithUserInfo:` 判斷該訊息是否由 Whale 下發，只有屬於 Whale 的訊息才需要透傳給 SDK：

```objective-c
NSDictionary *userInfo = /* 從自有推送通道收到的訊息字典 */;
if ([LBWhaleAppPushService checkIsLBNotificationWithUserInfo:userInfo]) {
    // 交由 SDK 處理（見下文步驟 2 / 步驟 3）
} else {
    // 非 Whale 訊息，Broker App 自行處理
}
```

#### 展示前臺 tip

App 處於前臺時收到 Whale 訊息，呼叫 `sdkShowTipWithNotificationInfo:routerHandler:` 讓 SDK 展示 tip，並在使用者點擊 tip 時透過 `routerHandler` 回調路由地址：

```objective-c
// 使用自定義封裝的引數處理前臺推送
NSDictionary *customNotification = @{
   // ...透傳服務端訊息字典
};

NSError *error = [LBWhaleApp.pushService sdkShowTipWithNotificationInfo:customNotification routerHandler:^(NSString * _Nonnull routerUrl) {
        /**
         1. 處理路由跳轉前的 Broker App 需要執行的自定義操作...
         2. 跳轉 block 回調的路由地址
        /
        // ... APP 自定義操作
        // 開啟路由跳轉
        [LBWhaleApp pushURL:routerUrl];
}];
if (!error) {
    // SDK 已處理通知
} else {
    // 處理錯誤或由 Broker App 自行處理
}
```

**注意**：實現了 `routerHandler` block 後，原跳轉不會再自動執行，如需正常完成預期的點擊 tip 跳轉頁面，需要在 block 中手動開啟 `routerUrl`。

#### 處理點擊跳轉

使用者點擊通知後，呼叫 `handleNotificationClickWithInfo:routerHandler:` 讓 SDK 完成路由跳轉，`routerHandler` 的行為與步驟 2 一致：

```objective-c
// 使用自定義封裝的引數處理推送點擊事件
NSDictionary *customResponse = @{
    // ...透傳服務端訊息字典
};

NSError *error = [LBWhaleApp.pushService handleNotificationClickWithInfo:customResponse routerHandler:^(NSString * _Nonnull routerUrl) {
    // ... APP 自定義操作
    // 開啟路由跳轉
    [LBWhaleApp pushURL:routerUrl];
}];
if (!error) {
    // SDK 已處理通知響應
} else {
    // 處理錯誤或由 Broker App 自行處理
}
```

### 自定義字型配置

SDK 支援自定義字型配置，允許 Broker App 替換 SDK 內建字型。透過在 `extraCustomConfig` 中配置字型映射，可以將 SDK 使用的字型替換為自定義字型。

    LBAPPSDKConfigKeyFontMonospacedBold: customMonospacedBoldFont,

    appName:appName

### 其他注意事項

WhaleAppSDK  在 podspec 中顯式聲明瞭其依賴的第三方庫清單

```ruby
spec.dependency 'RangersAPM/Crash', '>= 5.1.6'
spec.dependency 'RangersAPM/APMLog', '>= 5.1.6'
spec.dependency 'RangersAPM/CN', '>= 5.1.6'

spec.dependency 'AlicloudPush', '>= 3.2.2'
spec.dependency 'IQKeyboardManager', '>= 6.5.9'
```

這些第三方庫並未包含在在 SDK 二進位制檔案中。如果當前依賴的版本與您所使用的版本存在衝突，可採用註釋清單中的依賴解決。 例如，您專案中所使用的 IQKeyboardManager 為 IQKeyboardManagerSwift 版本，而 SDK 宣告的是 IQKeyboardManager Objective-C 版本。此時您可以手動註釋關於 podspec 中 IQKeyboardManager 的依賴。SDK 內部會動態依賴您 APP 中已經整合的 IQKeyboardManagerSwift 版本。
