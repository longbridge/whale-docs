## 1. 系統要求

- **Min Android SDK**：24
- **Target Android SDK**：35
- **JDK**：17+
- **Kotlin**：1.8.22+
- **AGP**：8.5.2+
- **Gradle**：8.7+
- **架構支援**：arm64-v8a、armeabi-v7a
- **開發語言**：Java、Kotlin
- **Android Studio**：建議使用 2025.1.3+；低版本如出現構建不相容請升級
- **其他**：不支援橫屏展示。

## 2. 整合方式

下載 `LBWhaleAppSDK-XXX.zip (內含 aar 和 Demo)` 解壓後將 SDK 目錄複製到專案目錄下， 在 App 級別的 `build.gradle` 的 `plugins` 下方新增下列程式碼匯入 SDK 配置檔案。

```groovy
//下方路徑示範是將 LBWhaleAppSDK 放置到 app 目錄下，實際路徑請根據 LBWhaleAppSDK 存放目錄進行調整
apply from: "${project.file('LBWhaleAppSDK/whale-sdk-config.gradle')}"
```

### 2.1 ARouter 預編譯最佳化（必須開啟）
SDK 內部使用 ARouter 進行路由，如**未開啟**預編譯最佳化將會**導致 init 方法耗時大幅度增加**，請在專案級別的 `build.gradle` 中新增如下外掛：
```groovy
buildscript {
    dependencies {
        //路徑請根據 LBWhaleAppSDK 實際存放位置調整
        classpath files('./../LBWhaleAppSDK/libs/lb-arouter-register-1.1.4.jar')
    }
}
```
在 App 級別的 `build.gradle` 的 `plugins` 中新增外掛：
```groovy
plugins {
    id("com.longbridge.arouter")
}
```

### 2.2 Kapt 和 Databinding
SDK 需要開啟 Kapt 和 DataBinding 支援，如原有專案已開啟可跳過該步驟，否則請按如下方式開啟。

專案級別的 `build.gradle` 中新增下列程式碼
```groovy
apply plugin: 'kotlin-kapt'
```

App 級別的 `build.gradle` 中新增下列程式碼
```groovy
plugins {
    id("org.jetbrains.kotlin.kapt")
}
android {
    buildFeatures {
        viewBinding = true
        dataBinding = true
    }
}
```

### 2.3 R8 編譯配置
打包 App 時，需要使用 R8 的相容模式，否則會導致 SDK 內部出現異常。 在專案根目錄的 `gradle.properties` 中進行如下配置。
```agsl
android.enableR8.fullMode=false
```

## 3. 初始化 SDK

在 `Application onCreate` 中呼叫 SDK 的 Init 方法進行必要資源的初始化準備，請在主執行緒呼叫該方法。

```kotlin
LBWhaleApp.init(application)
```
ps: 如未開啟 ARouter 預編譯最佳化，該方法耗時將會大幅度增加

## 4. 配置推送

### 4.1 方式一：走 SDK 內建渠道

SDK 內建阿里雲推送，相關的業務推送可透過該渠道推送至客戶端進行處理。

當收到推送時應用處於前臺會顯示**應用內通知**，當應用處於後臺時則會顯示**系統通知欄通知**。

如需使用內建阿里雲推送功能請在 SDK 初始化之後呼叫下面方法， `LBWhaleApp.pushService.init(application, pushConfig)` 需要在主執行緒呼叫。
```kotlin
val notificationConfig = NotificationConfig(
    notificationIcon = R.mipmap.logo_notification,
    notificationSmallIcon = R.mipmap.lb_push_small_notification,
    notificationChannelId = channelId,
)

//建立推送配置
val pushConfig = LBWhalePushConfig.Builder()
    .appKey(BuildConfig.ALIYUN_PUSH_APP_KEY)
    .appSecret(BuildConfig.ALIYUN_PUSH_APP_SECRET)
    .disableMultiDevice(false) //可選，是否關閉多裝置推送
    .notificationConfig(notificationConfig)
    .pushCallback(object : LBWhalePushCallback {
        override fun onNotificationOpened(title: String, summary: String, extMap: Map<String, String>) {
          //當通知欄通知被點擊後觸發該回調，需要在此判斷 SDK 是否正在執行
          //然後呼叫 handleNotificationOpened 方法處理點擊事件, 實現頁面跳轉
          if (LBWhaleApp.isStarted()) {
            LBWhaleApp.pushService.handleNotificationOpened(title, summary, extMap)
            return
          }
          //如 SDK 未啟動，需啟動 SDK 後再呼叫 handleNotificationOpened 進行處理
        }

        override fun onPushRegisterFailed(errorCode: String?, errorMessage: String?) {
          //推送通道註冊失敗時觸發該回調，需要檢查傳入的阿里雲配置引數是否正確
        }
    })
    .build()

//初始化推送服務
LBWhaleApp.pushService.init(this, pushConfig)
```

#### 4.1.1 廠商通道推送
SDK 內建的阿里雲推送支援相容第三方廠商通道，以達到提高推送到達率的效果。下方以 FCM 為例說明如何將 SDK 的業務訊息傳送至 FCM 訊息。

初始化 Firebase 後上報 FCM Token 到 SDK

```kotlin
FirebaseApp.initializeApp(this, options)
FirebaseMessaging.getInstance().token.addOnCompleteListener { task ->
  if (task.isSuccessful) {
    val token = task.result
    //將 token 上報到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }
}
```

在 FirebaseMessagingService 中更新 Token 以及處理訊息
```kotlin
class DemoFirebaseMessagingService : FirebaseMessagingService() {
  private val logger = SDKLogger.get(this::class)

  override fun onNewToken(token: String) {
    logger.i("onNewToken: $token")
    //將 token 上報到 SDK
    LBWhaleApp.pushService.repotThirdToken(this, LBWhalePushService.ThirdPush.FCM, token)
  }

  override fun onMessageReceived(message: RemoteMessage) {
    logger.i("onMessageReceived:${message.messageId}")
    //SDK 阿里雲推送投遞到 FCM  的訊息會攜帶 payload 欄位，可以根據這個特徵判斷 FCM 此處收到的訊息來源
    //如存在 payload 內容，需將其傳遞給 SDK 進行處理
    val msg = message.getData()["payload"]
    if(msg.isNotEmpty()){
      LBWhaleApp.pushService.onThirdPushMsg(this,LBWhalePushService.ThirdPush.FCM, msg)
    }
  }
}
```

### 4.2 方式二：走 Broker 自有渠道

Broker App 可以選擇自行接入第三方推送服務，業務訊息由 Whale 轉發至 Broker Server，再由 Broker Server 推送到 Broker App。
在收到訊息時可呼叫 SDK 方法對訊息進行解析處理，SDK 提供 `LBWhaleApp.pushService.handleNotificationReceived` 方法用於解析訊息並展示應用內通知。

### 4.3 通知事件處理
#### 4.3.1 通知展示
應用內通知展示
- SDK 內建渠道：SDK 內部處理通知展示
- Broker 自有渠道：可在收到訊息後呼叫 `LBWhaleApp.pushService.handleNotificationReceived` 進行訊息處理，該方法會解析訊息內容並展示，注意該方法需要在 SDK 啟動後才能生效

應用外通知展示
- SDK 內建渠道：SDK 內部處理通知展示
- Broker 自有渠道：由 App 自行處理

#### 4.3.2 通知點擊事件
應用內通知被點擊
- SDK 內建渠道：SDK 內部處理通知點擊事件
- Broker 自有渠道：如使用了 `LBWhaleApp.pushService.handleNotificationReceived` 方法處理訊息展示，則由 SDK 內部處理通知點擊事件，否則需由 App 處理

應用外通知被點擊
- SDK 內建渠道：透過 `LBWhalePushCallback` 回調給 App 進行處理，收到此回調時可選擇自行處理，也可以使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法處理該點擊事件，該方法將會解析通知內容並進行相關頁面的跳轉。注意該方法需要在 SDK 啟動後才能生效
- Broker 自有渠道：可使用 `LBWhaleApp.pushService.handleNotificationOpened` 方法處理點擊事件，該方法將會解析通知內容並進行相關頁面的跳轉。注意該方法需要在 SDK 啟動後才能生效

## 6. 實現 Callback 方法

```kotlin
LBWhaleApp.callback = object : LBWhaleAppCallback {
    //SDK 啟動成功時觸發，啟動成功後才可呼叫 LBWhaleApp 的相關方法
    override fun onLBWhaleAppStarted() {}

    //SDK 啟動失敗，錯誤型別請參考錯誤處理章節
    //可能的錯誤：InvalidConfig / InvalidAppKey / InvalidAppSecret / InvalidToken / TokenExpired / RefreshTokenExpired / RequestFailed / SyncAccountFailed
    override fun onLBWhaleAppStartFailed(error: Exception) {}

    //執行期間發生錯誤，錯誤型別請參考下方錯誤處理
    //可能的錯誤：
    //  - RefreshTokenExpired: 執行期間後端（refresh token 過期），需要業務方處理 SDK 登出和重新啟動
    //  - NotInitialized: 在 SDK 未啟動（status != STARTED）時呼叫了 pushUrl / changeTheme / changeLanguage / changePriceColor 等需要先 start 的方法
    //注：refresh_token 失效時先觸發 onLBWhaleAppRefreshTokenExpired；若未恢復，則會呼叫本方法丟擲 RefreshTokenExpired 錯誤
    override fun onLBWhaleAppRunInError(error: Exception) {}

    //SDK 自動續期成功後的通知；憑證有效性和後續續期仍由 SDK 管理
    override fun onLBWhaleAppTokenChanged(token: String, refreshToken: String) {}

    //SDK 請求跳轉其他路由時觸發，可在此解析 URL 並交給 Broker App 路由；該 URL 由 Broker 在服務端配置
    override fun onWhaleAppSdkOpenUrlRequested(url: String) {}

    //token 與 refresh_token 均無法續期時觸發。
    //預設實現會放棄重試，隨後進入不可恢復的鑑權失敗流程；Broker App 應銷燬 SDK 並返回登出狀態。
    //僅當專案另有約定並能取得一組全新的 Customer 憑證時，才呼叫 resolver.resolve(newToken, newRefreshToken)。
    override fun onLBWhaleAppRefreshTokenExpired(resolver: LBWhaleAppRefreshTokenResolver) {
        resolver.resolve("", "")
    }
}
```

<Note>
正常情況下，WhaleApp SDK 自動完成 token 校驗與續期，Broker App 不呼叫 check token 或 refresh token 介面。`onLBWhaleAppRefreshTokenExpired` 是極低機率異常的兜底擴充套件點，不應被實現為常規重新整理流程。
</Note>

## 7. 實現 UICallback 方法（可選）

`LBWhaleAppUICallback` 用於感知使用者**進入 / 退出 SDK 頁面**，與 `callback` 相互獨立，按需註冊。

- **進入 SDK**：開啟第一個 SDK 頁面時觸發（存活 SDK 頁面數 0 → 1）。
- **退出 SDK**：關閉所有 SDK 頁面時觸發（存活 SDK 頁面數 1 → 0）。
- 判定按頁面"是否存在"（onCreate / onDestroy），而非前後臺可見性：App 切到後臺但 SDK 頁面仍存活，不算退出。
- SDK 銷燬（`logoutAndDestroy`）時若仍停留在 SDK 頁面，會補發一次退出回調。
- 兩個回調均在主執行緒觸發，可直接操作 UI。介面方法均有預設空實現，可只實現關心的方法。

```kotlin
LBWhaleApp.uiCallback = object : LBWhaleAppUICallback {
    //進入 SDK：開啟第一個 SDK 頁面
    override fun onLBWhaleAppEnterSdkPage() {}

    //退出 SDK：關閉所有 SDK 頁面
    override fun onLBWhaleAppExitSdkPage() {}
}
```

## 9. 錯誤處理
```kotlin
sealed class LBWhaleAppError(message: String, cause: Throwable? = null) : Exception(message, cause) {
    //SDK Configuration Errors
    //呼叫 startWithConfig 時如果必要引數為空將透過 onLBWhaleAppStartFailed 返回該異常，請檢查啟動引數內容
    class InvalidConfig(field: String) : LBWhaleAppError("Invalid SDK config field: $field")

    //呼叫 SDK 方法時如果還未啟動 SDK 將會透過 onLBWhaleAppRunInError 返回該異常，請先啟動 SDK 再進行相關方法呼叫
    object NotInitialized : LBWhaleAppError("SDK not initialized")

    //SDK 啟動過程中獲取帳戶資訊失敗時透過 onLBWhaleAppStartFailed 返回該異常，可嘗試更換網路或直接重新啟動 SDK
    object SyncAccountFailed : LBWhaleAppError("Sync account status error")

    //Authentication Errors
    //呼叫 startWithConfig 時如果傳入的引數無效將透過 onLBWhaleAppStartFailed 返回該異常
    object InvalidAppKey : LBWhaleAppError("Invalid App Key provided")
    object InvalidAppSecret : LBWhaleAppError("Invalid App Secret provided")
    object InvalidToken : LBWhaleAppError("Access token is invalid")
    object TokenExpired : LBWhaleAppError("Access token has expired")

    //呼叫 startWithConfig 時如果傳入的 Refresh Token 無效將會在 onLBWhaleAppStartFailed 回調中返回該異常，請重新獲取相關 token 後再次啟動 SDK
    //如在 onLBWhaleAppRunInError 回調中收到該異常說明賬號在其他裝置進行了登入，請呼叫 logoutAndDestroy 登出 SDK，在重新獲取相關 token 後可再次啟動 SDK
    object RefreshTokenExpired : LBWhaleAppError("Refresh token has expired")

    //Network Request Errors
    //呼叫 startWithConfig 時如果發生其他網路請求錯誤將透過 onLBWhaleAppStartFailed 返回該異常，可嘗試更換網路或直接重新啟動 SDK
    class RequestFailed(message: String, val code: Int) : LBWhaleAppError("Request failed (code $code): $message")

    //Push Message Errors
    //呼叫 LBWhaleApp.pushService.handleNotificationOpened 處理訊息時如果檢測到非 LB 訊息則會返回該錯誤
    object UnrecognizedPushMessage : LBWhaleAppError("Unrecognized push message format")

    //呼叫 LBWhaleApp.pushService.handleNotificationOpened 時，LB 推送訊息但解析後跳轉 link 為空將返回該錯誤
    object MissingPushLink : LBWhaleAppError("Push message missing link")

    //SDK 內部未預期異常的統一包裝，cause 欄位保留原始 Throwable，可用於上報堆疊
    class InternalError(cause: Throwable, message: String? = cause.message)
        : LBWhaleAppError(message ?: "Internal SDK error", cause)
}
```

## 11. API 文件

### 11.1 LBWhaleApp

SDK 的主入口類，提供啟動、登出和頁面路由等核心功能。

```kotlin
//SDK 事件回調，需在 startWithConfig 之前賦值
var callback: LBWhaleAppCallback?

//SDK 頁面進入 / 退出回調（可選），建議在 startWithConfig 之前賦值
var uiCallback: LBWhaleAppUICallback?

//SDK 內建的推送服務例項
val pushService: LBWhalePushService

//初始化 SDK，debug 引數控制是否啟用除錯日誌
fun init(application: Application, debug: Boolean = false)

//啟動 SDK（非同步），啟動結果透過 LBWhaleAppCallback 回調
fun startWithConfig(application: Application, config: LBWhaleAppConfig)

//登出並銷燬 SDK，釋放記憶體與網路請求
fun logoutAndDestroy()

//跳轉到路由頁面
fun pushUrl(uriString: String, bundle: Bundle? = null, flags: Int? = null)

//更換主題
fun changeTheme(theme: LBWhaleAppConfigTheme)

//更換語言
fun changeLanguage(language: LBWhaleAppConfigLanguage)

//更換紅漲綠跌配置
fun changePriceColor(priceColor: LBWhaleAppConfigPriceColor)

//判斷 SDK 是否已啟動（status == STARTED）
fun isStarted(): Boolean

//獲取 SDK 當前狀態（IDLE / STARTING / STARTED / RELEASING）
fun getStatus(): Status

fun getVersion(): String

fun getAppId(): String
```

### 11.2 LBWhalePushService
透過 LBWhaleApp.pushService 獲取，用於管理推送服務相關能力
```kotlin
//初始化推送服務（需在主執行緒呼叫）
fun init(application: Application, pushConfig: LBWhalePushConfig)

//獲取推送服務裝置 ID
fun getPushDeviceId(): String

//上報第三方廠商通道（如 FCM）的 Token 到 SDK
fun repotThirdToken(context: Context, thirdPush: ThirdPush, token: String)

//將第三方廠商通道收到的訊息透傳給 SDK 進行解析處理
fun onThirdPushMsg(context: Context, thirdPush: ThirdPush, msg: String?)

//解析通知訊息並展示應用內通知（Broker 自有渠道收到訊息後呼叫）
//返回值為 LBWhaleAppResult<Unit>，可能失敗原因與 handleNotificationOpened 一致
fun handleNotificationReceived(
    title: String,
    summary: String,
    extraMap: Map<String, String>,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//直接接收完整標準訊息 JSON；SDK 解析 title、body 和 user_info
fun handleNotificationReceived(
    json: String,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//處理通知欄通知點擊事件
//返回 LBWhaleAppResult<Unit>，LBWhaleAppResult.Error 時 cause 可能為：
//  - LBWhaleAppError.NotInitialized          : SDK 未啟動（應先呼叫 LBWhaleApp.startWithConfig）
//  - LBWhaleAppError.UnrecognizedPushMessage : extMap 中缺少 lb_push_from 欄位，說明該訊息並非來自 LB 推送體系
//  - LBWhaleAppError.MissingPushLink         : LB 推送訊息但解析後跳轉 link 為空
//  - LBWhaleAppError.InternalError           : 路由 / 埋點等過程中丟擲的未預期異常的兜底包裝
fun handleNotificationOpened(
    title: String,
    summary: String,
    extMap: Map<String, String>,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>

//直接接收完整標準訊息 JSON，並處理通知點擊路由
fun handleNotificationOpened(
    json: String,
    callback: NotificationRouterCallback? = null
): LBWhaleAppResult<Unit>
```

`handleNotificationReceived` 和 `handleNotificationOpened` 返回 `LBWhaleAppResult<Unit>`。成功時為 `LBWhaleAppResult.Success`；失敗時為 `LBWhaleAppResult.Error`，透過 `cause` 讀取具體的 `LBWhaleAppError`。Broker 自有渠道應優先傳入[標準訊息結構](/zh-hk/docs/message-push/#標準訊息結構)，不要自行拆改 `user_info`。

### 11.12 LBWhaleAppCallback - SDK 事件回調

```kotlin
interface LBWhaleAppCallback {
    //SDK 啟動成功
    fun onLBWhaleAppStarted()

    //SDK 啟動失敗
    fun onLBWhaleAppStartFailed(error: Exception)

    //執行期間發生錯誤
    fun onLBWhaleAppRunInError(error: Exception)

    //SDK 自動續期成功後的通知；憑證有效性和後續續期仍由 SDK 管理
    fun onLBWhaleAppTokenChanged(token: String, refreshToken: String)

    //跳轉特定 Url 回調
    fun onWhaleAppSdkOpenUrlRequested(url: String)

    //SDK 分析事件回調；預設空實現，僅在專案需要承接分析事件時覆蓋
    fun onLBWhaleAppAnalyticsEvent(eventName: String, properties: JSONObject) {}

    /**
     * 當 refresh token 失效時觸發。
     * 可透過 resolver 返回一組全新的 token 和 refresh token，超時預設為 30s。
     * 預設實現立即 resolve("", "") 放棄重試，隨後由執行時錯誤回調通知 Broker App 退出登入。
     */
    fun onLBWhaleAppRefreshTokenExpired(resolver: LBWhaleAppRefreshTokenResolver) {
        resolver.resolve("", "")
    }
}
```

### 11.13 LBWhalePushCallback - 推送事件回調
```kotlin
interface LBWhalePushCallback {
    /**
     * 使用者點擊通知欄通知時觸發此回調。
     * 引數：title 通知標題、summary 通知摘要、extMap 阿里雲透傳的擴充套件欄位。
     * 建議在回調內判斷 SDK 是否已啟動，已啟動則呼叫 LBWhaleApp.pushService.handleNotificationOpened 完成跳轉，
     * 未啟動則需先啟動 SDK 後再處理。
     */
    fun onNotificationOpened(title: String, summary: String, extMap: Map<String, String>)

    /**
     * 推送通道（阿里雲）註冊失敗時回調，對應 iOS 的 NotificationErrorPushStartFailed。
     * 常見原因：appKey/appSecret 錯誤、AndroidManifest 包名與控制檯不一致、阿里雲控制檯未開通推送服務。
     * 注意：PUSH_20110（裝置已註冊）不會觸發此回調。
     */
    fun onPushRegisterFailed(errorCode: String?, errorMessage: String?) {}
}
```

    fun onLBWhaleAppExitSdkPage() {}
}
