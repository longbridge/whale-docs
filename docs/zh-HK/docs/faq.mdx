<Note>
本頁會隨著 Broker 與 Developer Customer 的高頻問題持續補充。
</Note>

<AccordionGroup>
  <Accordion title="我應該對接哪個 API？">
    取決於誰在呼叫、訪問誰的資料。見 [接入方式選擇](/zh-hk/docs/integration-options)，一張表給出答案。
  </Accordion>
  <Accordion title="如何獲取 BrokerAPI 憑證？">
    機構級 `ACCESS_TOKEN` 由 Whale 按 Broker 簽發。見 [鑑權](/zh-hk/broker-api/get-started/authentication)。
  </Accordion>
  <Accordion title="有測試環境嗎？">
    有 —— `https://b-api.longbridge.xyz`。API Playground 預設使用測試環境，試調不會影響生產資料。
  </Accordion>
  <Accordion title="提交開戶申請後多久能完成？應該多頻繁查詢？">
    開戶是非同步流程，耗時取決於審批配置和當時的任務量。無需人工審批的配置通常可在較短時間內完成，但呼叫方仍應以申請狀態為準。查詢間隔及限頻要求應在專案聯調時確認；實現時使用退避策略，達到成功或失敗終態後立即停止輪詢。
  </Accordion>
  <Accordion title="介面返回錯誤時應該看 HTTP 狀態還是響應體 code？">
    兩者都應記錄。歷史 Whale 介面可能使用 HTTP `400` 並在響應體 `code` 中給出更具體的業務錯誤；HTTP `200` 表示請求成功時，歷史約定無需再根據響應體 `code` 判斷失敗。新接入應以當前 API Reference 的錯誤模型為準。
  </Accordion>
  <Accordion title="出入金金額如何傳遞？">
    歷史調賬介面的出金和入金都傳正數，以 `direction` 區分方向，金額精度最高為兩位小數。該調賬場景不應呼叫資金凍結介面；呼叫方必須自行阻止超額出賬。業務碼和當前校驗規則以對應介面文件為準。
  </Accordion>
  <Accordion title="多市場或多個上手方需要由 Broker 區分嗎？">
    通常不需要。資金劃撥和對賬以 `account_no` 為準；不同市場的可交易範圍及換匯能力由帳戶配置決定。
  </Accordion>
</AccordionGroup>
