## 接入流程

## 服务端对接方式

```jsonc
method: POST

headers:
  - X-Api-Key 参数，值为 Broker 接口方提供的加密 Key
  - X-Trace-Id 参数，链路追踪和链条

request Body：
{
  "member_ids": ["客户编号"],
  "template_key": "模板Key",
  "post_id": "消息ID", // 唯一
  "channel": "push",
  "language": "zh-CN",
  "title": "消息标题",
  "body": "消息摘要",
  "template_params": {
    // 业务根据模板定义传入的参数
    "key": "value",
    "date": "2026-01-21",
    "url": "https://xxx",
  },
  "pre_params": {
    // 内置的预设变量参数
    "key": "value",
    "member_real_name": "张三"
  },
  "user_info": {
    "t": "xx", // 客户端埋点用
    "tn": "xx", // 客户端埋点用
    "id": "xx", // 客户端埋点用
    "lb_push_from": "xx", // 判断是 Whale 发的消息
    "link": "跳转链接",
    "json": "{ \"key\": \"value\" }" // 这里透传各业务自定义的数据
  }
}

response body：
{
  "success": true,
  "message": "success", // 接口错误信息
  "code": 0, // 0 表示成功，非 0 表示失败，失败目前不会重试
}
```

## SDK 消息对接格式

```json
{
    "title": " 消息标题", // 以下字段都是 SDK 需要的。
    "body": "消息摘要",
    "user_info": {
        // 透传 user_info 的内容
        "t": "xx", // 埋点用
        "tn": "xx", // 埋点用
        "id": "xx", // 埋点用
        "lb_push_from": "xx", // 判断是 LB 发的消息
        "link": "跳转链接",
        "json": "业务内容 JSON 字串"
    }
}
```

## 线上已有模板

- pre_function：内置函数说明，该函数是内部定义并实现的，截止目前使用到的函数都有在文档中

- templates：模板定义

- template_locales：模板多语言及配置

[下载完整模板文件](/files/whalesdk/gbltpl.zip)

```sql
tpl.xxx 是从请求 Body 的 template_params 中取出的参数

pre.xxx 是从请求 Body 的 pre_params 取出的参数

比如 {{stock_name(tpl.stock_counter_id)}} 中的 tpl.stock_counter_id 那么template_params 中的参数会是这样

template_params: {
  stock_counter_id: "ST/US/BABA"
}

```
