Broker App 开发涉及 Customer 用户管理，包括注册、登录、校验和鉴权。这里有两种方式：

- 用户体系由 Broker 自建

- 用户体系使用 Whale API



这两种模式在流程上有些区别。



用户信息都存储在 Broker 自己的系统内，Whale API 只在用户开户时做一次证券帐号和用户的关联。

## Broker 自建用户体系



用户信息都存储在 Broker 自己的系统内，Whale API 只在用户开户时做一次证券帐号和用户的关联。

1. 开户需要做一次信息关联

2. 查询账户信息时，需要判断用户是否已经开户成功，成功后则不需要在 WhaleAPI 查询信息

> 如果是注销流程，也差不多，Broker 系统需要保存一个待注销的状态，每次查询账户信息需要到 WhaleAPI 查询下账户状态
>
>

用户证券账户在开户场景下应该有以下状态：

- 未开户

- 待开户

- 开户成功

- 开户失败，需要失败原因



## 用户体系使用 Whale API

用户体系使用 Whale API，服务端并不是只做透传，需要根据场景做 API 调用的组合，Whale API 提供的都是相对原子化的接口，不同的场景需要进行组合。

1. 登陆后 Whale API 会颁发用户 token 和 refresh token，app 需要存下来

2. 对于需要登陆的接口，调用需要分三步：

    1. 调用 check token 接口，确认 token 未过期

        1. 如果过期，返回信息给 APP，APP 需要发起 refresh token 调用重新获取 token

    2. 检查调用信息不会越权

    3. 发起调用

3. 退出登陆会让 token 和 refresh_token 都失效
