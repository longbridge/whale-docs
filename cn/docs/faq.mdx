<Note>
本页会随着券商与开发者的高频问题持续补充。
</Note>

<AccordionGroup>
  <Accordion title="我应该对接哪个 API？">
    取决于谁在调用、访问谁的数据。见[接入方式选择](/cn/docs/integration-options)，一张表给出答案。
  </Accordion>
  <Accordion title="如何获取 Broker API 凭证？">
    机构级 `ACCESS_TOKEN` 由 Longport Whale 按券商签发。见[鉴权](/cn/broker-api/get-started/authentication)。
  </Accordion>
  <Accordion title="有测试环境吗？">
    有 —— `https://b-api.longbridge.xyz`。API Playground 默认使用测试环境，试调不会影响生产数据。
  </Accordion>
  <Accordion title="提交开户申请后多久能完成？应该多频繁查询？">
    开户是异步流程，耗时取决于审批配置和当时的任务量。无需人工审批的配置通常可在较短时间内完成，但调用方仍应以申请状态为准。查询间隔及限频要求应在项目联调时确认；实现时使用退避策略，达到成功或失败终态后立即停止轮询。
  </Accordion>
  <Accordion title="接口返回错误时应该看 HTTP 状态还是响应体 code？">
    两者都应记录。历史 Whale 接口可能使用 HTTP `400` 并在响应体 `code` 中给出更具体的业务错误；HTTP `200` 表示请求成功时，历史约定无需再根据响应体 `code` 判断失败。新接入应以当前 API Reference 的错误模型为准。
  </Accordion>
  <Accordion title="出入金金额如何传递？">
    历史调账接口的出金和入金都传正数，以 `direction` 区分方向，金额精度最高为两位小数。该调账场景不应调用资金冻结接口；调用方必须自行阻止超额出账。业务码和当前校验规则以对应接口文档为准。
  </Accordion>
  <Accordion title="多市场或多个上手方需要由 Broker 区分吗？">
    通常不需要。资金划拨和对账以 `account_no` 为准；不同市场的可交易范围及换汇能力由账户配置决定。
  </Accordion>
</AccordionGroup>
