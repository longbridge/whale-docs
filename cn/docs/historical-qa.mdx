## 历史 Q \& A

### 提交开户申请后，大概多久能审核通过，后续建议的查询的频率是什么？有没有限频？

如果是配置的无需审批直接开户完成，那么是通过异步任务来完成，要看当前并发量，可以几 s 查一次



### 调账接口：出入金接口的 bizCode 是什么？都是 OPLCSTBD？ 无论出金还是入金都是，金额都是传正数?

可以参考 https://apidocs.longbridgewhale.com/whaleapi/asset-348068f0 的业务码。出入金都是传正数。通过 direction 区分



### 调账接口：出入金的精度，是不是最高到2位？ 用户的账户里会有超过2位精度的金额吗？

精度最高到 2 位小数，账户保存也是 2 位小数



### 所有报错的请求 http 的 code 都是 400，但是 body 里的 code 是 404002 或 404102 这样的数字？

是的，当有错误的时候，以 body 的 code 错误码为准。



### 所有正常的 http 请求，status code 都是 200， 且 body 里的 code 都是 0?

是的，status code 为 200 的时候，不用考虑 `code` 参数



### uat环境的域名是不是可以先给出，我们先找运维配置出网

https://api.longbridgewhale.com



### 调账的时候，是否需要调用冻结资金接口，是不是不需要考虑。直接用调账接口就可以了。

调账的接口，不需要冻结， 直接调用接口就行（但是这里的调账目前出账是不校验风控的，可以超额出），超额问题需要调用方自己控制好。不要调用那个冻结接口，那个不是为调账设计的。



## 客户对接，HK、US 有可能是多个上手，在资金划拨、对账的时候，Broker 那边是否需要考虑后面上手是什么，还是以 account_no 为准就好了，他们不用管。

这个问题跟我会上解答是一样的，他们不用关心上手是谁，只看 account_no，钱进入证券账户以后可以换汇分别买卖 US、HK 股票的。
