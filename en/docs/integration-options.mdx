Longport Whale offers one embedded-client product and three APIs. The right choice depends on **who is calling** and **whose data the call is authorized to access**.

## Compare the options

| Product | Caller | Authorization subject | Private data scope | Form | Status |
| --- | --- | --- | --- | --- | --- |
| [WhaleSDK](/en/whalesdk/overview) | Broker app teams | **Customer** | Single customer | iOS / Android / WebTrade UI | Available |
| [Broker API](/en/broker-api/overview) | Broker backend services | **Broker** | Approved broker-wide scope | Server-to-Server | Available |
| [WhaleCore + Trading API](/en/trading-api/introduction) | Broker App | **Customer** | Single customer | Data SDK + HTTP API | iOS / Android available; WebAssembly in development |
| [OpenAPI ↗](https://open.longportapp.com) | Broker Developer Customers, AI apps | **Customer** | Single customer | Open API / SDK / MCP | Available for algorithmic trading, quantitative analysis, and AI access to customer-authorized account and market data |

## How to choose

- **Ready-made UI vs fully custom UI** — use **WhaleSDK** for a complete trading UI in the Broker App; use **WhaleCore + Trading API** when the Broker builds the securities UI from scratch. WhaleCore provides market-data subscriptions, WebSocket connectivity, request signing, and token renewal without UI.
- **Institution vs customer authorization** — backend integrations acting on behalf of the broker use **Broker API**; anything acting as a single end customer belongs to **Trading API** or **OpenAPI**.
- **Broker developers vs developer customers** — Broker Developers represent the broker; Developer Customers are the broker's clients. Even when both call similar quote or trading capabilities, they never share authorization models.

<Note>
"Public" platform content (quotes, fundamentals, news) is still served by its owning API product — public does not mean unauthenticated.
</Note>
